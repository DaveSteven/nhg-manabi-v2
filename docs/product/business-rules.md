# 作答、抽题与学习统计的统一业务规则

> 这些规则约束前端、API、数据库、统计计算和测试用例。具体字段结构以 PostgreSQL Schema v0.2 为准。

## 业务单位

`Exam → Section → Layer → Unit → Question → Option`。**Layer≠共享材料**；独立 Question 由转换器包为 `single` Unit；一个 Unit 可以含多个 Question；完整 Unit 才能被抽样和提交。科目 Section 是内容分类，模拟 Phase 是真实考试阶段，不互相推导。

## 会话状态

| 字段 | 值 | 语义 |
|---|---|---|
| `mode` | `practice / mock` | 普通练习可跨卷；mock 固定整卷 release |
| `feedback_mode` | `immediate / end` | mock 固定到交卷后揭晓 |
| `state` | `in_progress` | 可恢复、未产生完整成绩 |
| `state` | `completed` | 正式完成/交卷，产生结果 |
| `state` | `ended_early` | 主动结束，已提交逐题历史保留，不生成完整成绩 |
| `state` | `abandoned` | 无有效正式作答被放弃，不生成成绩 |

当前方案：每个账号最多一个活跃 ordinary practice；新练习提醒用户，选择继续旧练习或开始新练习（旧练习结束）。**模考是否允许另占一个活跃名额仍须确认。** 浏览器关闭、断线、刷新都不改变 Session 的 `in_progress` 状态；严格模拟的计时由服务端继续进行。

## 草稿与正式作答

- 每次选项选择及修改是草稿；已选但未提交，不计入正确率、不改变错题状态。
- `immediate`: 用户明确提交**整个 Unit**；服务端原子判题、锁定该 Unit，揭晓该 Unit 的答案和解释。Unit 内未选也随同标记 skipped。
- `end`: 用户提交整次 Session 后才批量锁定、揭晓；提交之前可修改已选草稿。
- 严格 mock：独立阶段/倒计时、交卷后才揭晓；前端不能收到尚无权查看的 correct_option_id 或解析。
- 提交 Unit、交卷和结束会话必须幂等；跨设备草稿用 `row_version`/预期版本，防旧请求覆盖。
- 提交前若存在未选题目，必须明确提示数量；允许返回补答或确认提交。

## 统计口径（不可混用）

- **本次得分率** `correct_count / total_count`，分母包含正式提交时跳过的题。
- **已作答正确率** `correct_count / (correct_count + wrong_count)`，跳过不计入分母；分母为 0 时显示 “—”，不得展示 0% 当作已答错。
- `user_question_progress` 是从 immutable submitted answers 派生的缓存，可重建；`attempt_count` 应明确代表有实际作答的次数，另存 `skip_count` 代表正式提交但未选次数。
- 覆盖率：在可练习题库范围内，至少有一次**有效正式回答**的去重 Question 数 / 范围中可发布 Question 数；范围变动须解释。
- 模考和普通练习的成绩展示、趋势、来源分开，不混入一个“官方换算分”。

## 错题策略 B

- `曾经答错`：历史存在 `is_correct=false` 且有真实选择的记录；永不自动删除历史。
- `最近仍错`：最近一次**有效有答案**的提交为错。
- `最近已答对`：曾错过，最近有效有答案的提交为对。
- skip 不新增错题、不更新最近有效答对/答错；在最近一次“遇到记录”仍可以注明跳过。
- 单纯选择草稿、关闭浏览器、未提交，不改变任何错题指标。

## 智能随机抽样

- 选择等级 + **单一题型** + 数量；数量是 Unit 数（单题题型显示“题”，阅读/音频显示“篇/组”）。
- 只从有可用完整 Unit 且通过发布门槛的候选池抽取；同一 Session 同一 Question 不能重复；同一个 Unit 不可拆分。
- 初始**软配额**约 70–80% 未见/未正式做过 Unit，20–30% 已练但薄弱、低频或久未复习 Unit；候选不足自动弹性调节。
- 权重综合次数、正确率、最近有效正误、最近一次练习时间；正确率样本过少不能极端放大；避免紧邻重复，保留随机性，不能永久只挑“最难”。
- “再练一组”复用配置而非复用题号；“只复习最近仍错”应作为独立动作，不混入默认新题探索逻辑。

## 真实试卷练习和模考

- 从试卷详情点一个 Unit 直接开始；是否加“练习本大题”仍待确认。
- 单题完成就地反馈；多题生成简洁结果和按 Unit 回顾；回顾必须有当时题干、选项、共享材料、媒体、选择、答案版本。
- 严格模拟必须使用经核实的 Phase 时间/音频规则；刷新不重置时限；不可在交卷前经任何接口泄漏正确答案。
- 考试官方尺度分、合格判断和听力播放控制等未经可信来源核实，不可冒充正式 JLPT 评分或考试规定。

## 边界用例

1. 20 题，12 对、5 错、3 skip → 本次得分率 60%，已作答正确率 12/17 ≈ 70.6%。
2. 同一篇 3 问题，前两道提交后才想到第三道：即时反馈模式不允许只提前提交其中 2 题；提交 Unit 时第三道可标 skip。
3. 昨天错、今天对、明天 skip → 历史仍含错，最近有效仍为对。
4. 新建普通练习替换未完成会话 → 保留旧会话已**正式**提交的答案，未提交草稿不计历史。
5. 用户作答期间发布新版答案 → 老会话继续关联旧 release，旧成绩不得自动重写。
