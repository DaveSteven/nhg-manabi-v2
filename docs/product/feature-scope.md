# 功能范围与迭代路线

> 开发优先级是规划建议，不是完成状态。以 **纵向切片** 验收，不先写完全部后端再开始前端。

| 里程碑 | 最小交付 | 主要验收标准 |
|---|---|---|
| M0 文档与基础设施 | 规范、AGENTS.md、独立 Docker PG、Alembic | 文档冲突已标注；真实开发库迁移 + 可回滚 |
| M1 内容底座 | Canonical → staging 幂等导入、目录和 Unit 查询 | 五套样本 20 Section / 83 Layer / 440 Unit / 498 Question / 204 Asset；两次导入无重复；草稿不可公开 |
| M2 第一个可用练习闭环 | N2 试卷目录→大题/Unit→答题→提交→解析 | 真实题目 UI 渲染 + API 贯通；不泄漏答案；一组多题整体反馈 |
| M3 用户学习 | 账号、保存恢复、题目历史、错题、随机选题 | 仅一个普通活跃练习；历史错题 B；20%-30% 复习池软配额 |
| M4 模考 | 服务端限时 Phase、严格作答、完整成绩 | 刷新不重置计时；无可靠时限则不开放严格模拟；规则见 ADR-0019（已定，未实现） |
| M5 后台与上线 | 题目审核/发布、音视频、部署监控、基本运维 | Agent 结果与人工放行分开；授权/质量门槛；独立生产部署与回滚 |

## 首期明确排除

AI 精读、重型推荐系统、排行榜、积分、连续签到、复杂商业付费、国际化、自动推送目标、全文重制旧版页面。不应因为这些功能曾在 1.0 出现就自动纳入。

## 依赖与并行

- 校验 Agent 对 N5–N1 内容做语言学校验可与开发并行；结构验证通过不等于答案/解析已校验。
- 前端可先使用已验证结构的测试包；未取得发布许可或未审核内容不能对外公开发布。
- M1/M2 只需足够完成的数据库、API 和 UI，不要求全部 32 张表的业务能力先行实现。
