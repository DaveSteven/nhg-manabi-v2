# JLPT GO 2.0 · 产品需求基线（2026-11-15）

> 本文整合之前的 2.0 讨论，仍区分「已确认方向」与「需要验证/确认」。详细交互以 `design/practice-interactions.md` 为准，数据规范以 `architecture/canonical-schema-v2.0.md` 为准。早期 PRD v0.1 保留在 `reference/prior-drafts/`，其中“进行中会话待确认”等较早条款已由后续决定修订。

## 定位

面向 JLPT N5–N1 考生的 **历年试卷、专题高效率练习、严格模拟、学习复盘** 平台；PC-first 但移动端可完成主要学习路径。用户常见场景是快速找真题、按一个题型抽题、提交回顾、查看最近仍错并复练；不是游戏化打卡工具。

## 顶层信息架构（已确认）

- 顶部水平导航：`首页` / `专项练习` / `历年试卷` / `我的学习`；右侧账户入口。无需全站侧边栏。
- 首页四个首要行动：**文字词汇 / 文法 / 读解 / 听力**。有进行中的普通练习时在上方出现轻薄「继续练习」条；否则不占位。
- 首页只留简洁的历年试卷入口、次级「强化练习」；考试倒计时和个性化建议可有但不可抢主任务；不放巨大 Hero、堆叠卡片仪表盘、首页 Tab 或打卡强引导。
- 试卷目录按 N 级、年份和会期筛选；详情页有「完整模拟」独立 CTA、四科扁平 tabs 和逐大题可展开的 Unit 列表；单 Unit 点击直达练习。
- 「我的学习」以行动价值为准：学习概览、练习历史、题目记录（含错题/收藏）是建议结构，避免做堆砌图表的 Dashboard。

## 核心功能范围（已确认的业务规则）

1. 每道 Question 恰好属于一个 Unit；独立题也有 Unit。Unit 是展示、智能抽取、即时反馈的最小不可拆分单位。
2. 专项随机：一次仅选**等级 + 单一题型 + 数量**，单题数按题、材料组数按篇/组。默认智能随机，初始策略约 70–80% 新题 + 20–30% 巩固题（软配额），避免刚做过的 Unit 频繁重复。
3. 选择选项 ≠ 提交。即时反馈必须按整个 Unit 正式提交后展示；统一反馈在整次 Session 结束后展示；严格模拟交卷前不返回答案或解析。
4. 允许带未答提交；提交前显示未答数量和确认选择；未答不等于答错，不自动入错题本；提交后锁定本次答案。
5. 历史曾错永久保留，筛 `曾经答错 / 最近仍错 / 最近已答对`。最近有效结果只由**有实际选择的正式作答**更新，skip 不改变最近正误。
6. 服务端保存并恢复；普通练习同时最多一个进行中的会话（当前方案），新开需提醒替换；关闭页面不是主动结束；提前结束不伪造完整练习成绩。
7. 单题反馈就地呈现；多题结果精简；共享材料按材料复盘；严格模拟提供独立成绩与整卷回顾。
8. 听力普通训练桌面/移动都用**单一固定底部播放器**，内容区为播放器留空间；严格模拟播放器行为单独限制。
9. 发布内容有不可变 release 和内部来源映射；题目校验工作与产品开发并行；不得未经审核公开发布草稿数据。

## 非功能要求

- 长篇日文、Ruby、下划线、填空锚点、图片、音频、字幕等经受控 RichText v1 安全展示；不得无损性未验证就裁剪源内容。
- 可键盘操作，有焦点可见、错误信息不靠颜色、触控目标建议 ≥44px；适配常见桌面/移动设备。
- 保存成功仅在服务端确认后提示；断网提供未保存状态和重试；请求幂等、草稿乐观锁；历史成绩可追溯。
- API 访问严格隔离私有答案与其他用户历史；审查发布版权/授权与内容质量分开。

## 暂未确定与待验证

- 严格模拟不同考试阶段的真实时长、音频播放规则、暂停和超时行为；未核实则不启用严格模式。
- 单独的“练习本大题”快捷操作、普通听力倍速/拖动细节、模拟并发规则。
- 读解 32–36 题型命名，N1/N2 A/B 比较材料切分；校验 Agent 的人工复核门槛。
- 旧版账户与历史数据是否迁移，邮箱注册时点，暗色细节及精确 UI 断点。

## 非首期需求

AI 精读、AI 造句、付费订阅、国际化、广告投放、排行榜与高复杂度学习计划。未来要做须有独立评审和增量 ADR。

## 首个纵向验收场景

访问 N2 试卷 → 展开文法问题或阅读文章 → 显示完整 Unit → 草稿选项可变更 → 正式提交 → 按模式揭晓反馈 → 服务端生成可追溯作答历史。包含一篇多题、一次未答提交、一次刷新恢复。
