# JLPT GO 2.0 · 视觉设计语言 v1.1

- **设计主题：** 樱与墨 · Modern Minimal
- **设计定位：** Japanese Minimal × Modern Digital Product
- **适用范围：** JLPT GO 2.0 用户端
- **设计状态：** 已确认的视觉方向与第一版实施规范

> 修订说明（2026-11-16）：本版取代此前的 Design System v2 草案。主要变化：顶部导航改为居中胶囊容器（Active 浅樱底，不再用底部选中线，页面级 Tab 仍保持下划线）；色彩 Token 更名并调整部分色值（`primary-soft`、`primary-hover`、`border` 等）；新增内容最大宽度 1200–1280px、导航宽度 560–600px 等量化建议；§13.1 新增基准 `:root` Token 清单。前端 `apps/web/app/styles/tokens.scss` 尚使用旧 Token 名与部分旧值，需另行对齐（见当日 devlog）。

## 1. 设计理念

JLPT GO 2.0 是面向 JLPT 备考学习者的现代数字学习平台。

视觉设计以「安静、轻盈、高效、精致」为核心，结合日式审美的克制和现代 Web App 的交互体验。

### 设计关键词

- **Minimal**：减少不必要的装饰和组件。
- **Calm**：柔和背景、舒适留白、低视觉噪声。
- **Focused**：强调用户正在进行的学习任务。
- **Modern**：轻量胶囊导航、精确排版、细腻交互。
- **Japanese-inspired**：以材质、色彩、节奏体现日式审美，而不是堆砌传统文化符号。

### 设计原则

1. 内容与操作优先于装饰。
2. 使用排版与留白建立视觉层次。
3. 樱色只用于重要交互及少量品牌表达。
4. 避免在所有区域重复使用卡片和边框。
5. 保留品牌个性，但学习页面必须高效。
6. 不为了视觉效果牺牲日文阅读和答题体验。

### 明确避免

- 传统网站式通栏导航。
- 大面积樱花、富士山、寺庙插画。
- 过度玻璃拟态与模糊背景。
- 大量彩色渐变。
- 每个内容模块都使用厚边框。
- 过多悬浮按钮和装饰性徽章。
- 夸张的 Hover 动画。
- 以 Dashboard 图表堆叠填充首页。

## 2. 色彩系统

### 2.1 品牌核心色

| Token | 色值 | 用途 |
|---|---|---|
| `--color-bg` | `#FAF7F2` | 页面主背景，和纸暖白 |
| `--color-surface` | `#FFFFFF` | 卡片、导航和弹层 |
| `--color-ink` | `#2B2B33` | 标题、主要文字 |
| `--color-primary` | `#B94968` | 深樱色，品牌强调 |
| `--color-primary-hover` | `#A53C5B` | 主要按钮 Hover |
| `--color-primary-soft` | `#F6E8EC` | 选中态、轻强调 |

### 2.2 中性色

| Token | 色值 | 用途 |
|---|---|---|
| `--color-text-secondary` | `#706B70` | 次要信息 |
| `--color-text-muted` | `#88838A` | 辅助说明 |
| `--color-border` | `#E8E3DF` | 轻量分隔线 |
| `--color-surface-subtle` | `#F4F1ED` | 图标底色、次级容器 |

### 2.3 色彩使用规则

- 整体以暖白、墨色和深樱为核心。
- 主要按钮使用深樱色。
- 普通卡片保持白色或极浅背景。
- 分类卡允许使用低饱和色作为小面积装饰。
- 分类颜色不应替代统一的交互状态颜色。
- 正确、错误和警告拥有独立语义色，不能将樱色用于所有状态。
- 不能只通过颜色区分答题正误。

首页允许出现少量淡粉、灰紫、浅绿、暖杏作为装饰性辅助色，但不将其扩展成四套独立主题。

## 3. 顶部导航系统

### 3.1 桌面端整体结构

采用「左侧品牌 + 居中胶囊导航 + 右侧用户控制」的布局。

**品牌 Logo**

- 位于页面左侧。
- 使用现有 JLPT GO 品牌标识。
- 不与主导航强行包在同一胶囊容器内。

**主导航**

- 页面水平居中。
- 独立胶囊式浮动容器。
- 固定视觉宽度，建议 `560–600px`。
- 高度建议 `56px`。
- 采用完全圆角。
- 白色或半透明暖白背景。
- 使用非常轻的阴影。
- 不使用通栏背景色或底部整行分割线。

包含四个入口：

`首页` / `专项练习` / `历年试卷` / `我的学习`

导航项允许在胶囊内部使用短标签，例如：

`首页` / `专项` / `试卷` / `学习`

前提是保持准确、易理解的导航语义。

**用户控制**

- 位于右侧。
- 放置头像及必要账户入口。
- 等级选择不强制放入主导航，应根据页面上下文显示。

**吸顶态（Sticky）**（2026-11-16，用户指示）

页面滚动超过 8px 后（`.site-header.is-stuck`），整行 `header-row`（品牌 + 导航 + 用户控制）变为**一个胶囊容器**，浮在内容上方：

| 项 | 规范 |
|---|---|
| 背景 | 半透明暖白 `rgba(255,255,255,0.78)` + `backdrop-filter: blur(14px) saturate(1.4)` |
| 边框/阴影 | 1px `--color-border`，`--shadow-floating` |
| 圆角 | 36px（单行时呈胶囊；窄屏多行折叠时保持圆角矩形，不用 999px 以免变成椭圆） |
| 过渡 | 背景、边框、阴影、模糊同步过渡，`--motion-normal`（220ms）`ease`；`prefers-reduced-motion` 下无过渡 |
| 导航胶囊 | 吸顶态下 `.topnav` **背景完全透明**（同时无阴影），由外层胶囊作为唯一的外壳；回到顶部（取消吸顶）后再渐变回白色（`rgba(255,255,255,0.92)` + 浅阴影）。背景、阴影与 `header-row` 使用相同的 220ms `ease` 过渡，两层外壳同步交替。**`.topnav` 不使用 `backdrop-filter`**：它嵌套在带 `backdrop-filter` 的外层胶囊内，嵌套的 backdrop-filter 即使设为 `blur(0)` 也会继续绘制一层，导致看不到透明效果 |
| 不位移 | 内边距在两种状态下相同（`8px 16px`，由等量负外边距抵消），切换时品牌、导航、控件和页面内容都不移动，只有「外壳」淡入 |
| 回到顶部 | 恢复透明、无边框、无阴影（与 §3.1 的「不使用通栏背景色」一致：静止态仍无任何容器） |

此条取代 §3.1「Logo 不与主导航强行包在同一胶囊容器内」在吸顶态的适用范围：静止态仍然是分离的 Logo / 导航胶囊 / 控件；仅吸顶态在整行外加一层半透明胶囊。

### 3.2 导航状态

| 状态 | 视觉规则 |
|---|---|
| Default | 透明背景、墨色文字 |
| Hover | 极浅暖灰或浅樱背景 |
| Active | 浅樱底色、深樱文字 |
| Focus | 清晰可见的键盘焦点轮廓 |
| Disabled | 降低对比度且不可交互 |

导航状态主要依靠浅底色表达。

**不使用传统的红色底部选中线。**

### 3.3 导航定位

桌面端可以采用 Sticky 导航：

- 顶部保留约 `16–20px` 空间。
- 滚动时保持居中。
- 背景支持适度 Backdrop Blur。
- 避免强玻璃质感和明显阴影。

滚动中导航不能遮挡重要内容。

### 3.4 移动端导航

移动端不强行保留桌面宽度。

建议：

- Logo 和头像使用紧凑布局。
- 主导航使用可适配视口宽度的胶囊容器。
- 空间不足时采用横向滚动或经过专门设计的紧凑导航。
- 不截断关键标签。
- 保留清晰选中态和触控区域。

### 3.6 面包屑导航（二级页面）

二级页面（如试卷详情）在 `h1` 上方放一条**纯文字**面包屑，取代原来的「返回列表」链接。

| 项 | 规范 |
|---|---|
| 形式 | 无背景、无边框、无胶囊；文字 14px |
| 结构 | `试卷 › 详情`：祖先项为链接（次要色，悬停变品牌色 `--color-primary`），**当前页**为普通文字（墨色、600 字重，`aria-current="page"`） |
| 分隔符 | 装饰性 `›`（`aria-hidden`），次要灰，不属于内容 |
| 位置 | `h1` 之上，下外边距 12px；与页面内容左对齐 |
| 无障碍 | `nav[aria-label="面包屑"]` + `ol`；链接有可见焦点环；颜色之外靠位置与字重区分当前页 |
| 层级 | 随页面层级增长：试卷详情 `试卷 › 详情`；练习页 `试卷 › 详情 › 练习`；结果页 `试卷 › 详情 › 结果`（含提前结束/未完成状态）。中间的「详情」链接到该会话所属试卷（来自会话 Unit 的 `exam_id`）；取不到时省略「详情」而不是指向错误页面。顶级页面（首页、试卷列表、用户中心）不显示面包屑 |

## 4. 页面布局

### 4.1 全局容器

桌面端采用居中布局。

建议：

- 内容最大宽度：`1200–1280px`
- 左右留白：大屏约 `48px`，普通桌面 `32px`
- 平板左右留白：`24px`
- 手机左右留白：`16px`

不应为了填满宽屏而无限拉伸内容。

### 4.2 空间系统

使用基于 4px 的间距系统：

| Token | 尺寸 |
|---|---|
| XS | 4px |
| SM | 8px |
| MD | 12px |
| Base | 16px |
| LG | 24px |
| XL | 32px |
| 2XL | 48px |
| 3XL | 64px |

组件内部一般使用 12–24px。

页面模块之间一般使用 32–48px。

整体通过留白建立层次，减少不必要的分割线。

## 5. 首页布局语言

### 5.1 页面定位

`/study` 是学习首页，不是品牌宣传页。

必须优先展示：

1. 当前学习目标或等级。
2. 未完成练习的恢复入口。
3. 四个专项练习入口。
4. 历年试卷快捷入口。

不使用大面积营销 Hero 或多个宣传按钮。

### 5.2 顶部信息区

采用简洁标题：

「从 JLPT 开始，不止于考试」

辅助说明：

「选一个科目，专注下一组练习。」

标题建议 30–36px（桌面），移动端 24–28px。

目标等级选择器可以放在右侧，与标题保持视觉平衡。

不要求出现复杂统计或欢迎模块。

### 5.3 装饰元素

首页可以有极少量装饰：

- 柔和的抽象圆形。
- 非具象的浅樱色形状。
- 少量日式线条或几何图形。

原则：

- 同一屏幕最多设置一个主要装饰区域。
- 装饰不能与正文、按钮或练习卡片竞争视觉注意力。
- 不使用大面积樱花树、富士山或传统寺庙插画。
- 不引入持续飘落的花瓣动画。

装饰应可以被关闭，而不影响页面布局。

## 6. 卡片设计

### 6.1 通用卡片

标准卡片采用：

- 白色背景。
- 轻微阴影；**首页上的卡片（继续练习、专项练习、历年试卷快捷入口）不加边框**（2026-11-16 用户决定，其余页面的普通 `.card` 仍可保留 1px 轻边框）。
- 中等圆角。
- 较宽松的内部留白。
- 无复杂渐变。
- 无厚重阴影。

卡片强调来自内容、排版和交互反馈，而非彩色边框。

### 6.2 专项练习卡片

四个核心科目：

- 文字词汇
- 文法
- 读解
- 听力

每个卡片包含：

1. 统一风格的线性图标。
2. 清晰的科目名称。
3. 一行简短说明。
4. 开始练习的操作入口。

桌面端建议四列排列。

**不使用角落装饰**（2026-11-16 去掉原先右下角的浅色圆形装饰 `::after`，也不使用大面积复杂插画）；科目差异只通过左上角图标的小面积浅色底表达。

Hover：

- 卡片轻微提升。
- 阴影稍微加强。
- 箭头或文字出现深樱色强调。

避免使用整张卡片的明显彩色描边。

**实现约束（2026-11-16）：** 专项练习卡片是**普通容器元素（`div`），不是 `button`**，也**没有边框**。四个科目的「练习」入口暂未开放（`专项练习暂未开放 · 可先用历年试卷`），在开放前卡片不可交互、不可聚焦、光标为默认；开放后应把可点击区域做成链接（`a`）而不是按钮，并恢复上述 Hover 效果。

### 6.3 继续练习模块

继续练习是首页最高优先级的操作之一。

要求：

- 只在存在有效进行中会话时出现。
- 优先显示试卷、等级、科目及进度。
- 主要按钮为「继续练习」。
- 使用普通卡片层次，不需要特殊渐变或大插画。
- 在手机端保持操作按钮明显。

### 6.4 历年试卷列表与卡片

历年试卷按**年份分行、最新年份在前**，每行两栏：左栏为年份（主要视觉信息），右栏为该年各会期的**月份胶囊卡片**（见 §6.5）。行与行之间用间距分隔，不画分隔线；页面没有筛选控件，等级跟随右上角备考等级。

不使用与专项练习相同的大尺寸卡片结构。

### 6.5 月份胶囊卡片（Capsule Card）

| 项 | 规范 |
|---|---|
| **标准高度** | **56px**（Token `--capsule-height`，2026-11-16 由 44px 调高）；年份文字行高与之相同，使年份与胶囊垂直居中对齐 |
| 形状 | 胶囊（`--radius-pill`），白底（`--color-surface`），**无边框**，`--shadow-card`（2026-11-16 去掉 1px 边框） |
| 宽度 | 块级，充满所在列；列由数据中的月份种类推导（≤4 种且同行无同月多份时，胶囊落在自己月份的列；否则两列顺序排列；只有一种月份时单列） |
| 内容 | 左对齐：月份（600 字重）；未设置备考等级时紧随其后附等级小标签；右侧靠右显示试题数量（`96 题`，次要色、等宽数字，13px） |
| 内边距 | 左右 `--space-6`（24px） |
| Hover | 文字变为品牌色 `--color-primary`，上浮 1px，阴影加强为 `--shadow-floating`（无边框可变色；尊重 `prefers-reduced-motion`）；不使用灰色底 |
| Focus | 2px 品牌色焦点环，偏移 2px |
| 无障碍 | 可访问名称为完整标题加题数（如「2025年12月 N2，101 题」）；触控高度 ≥ 44px |

**适用范围：** 历年试卷列表的月份胶囊；**试卷详情页的所有条目**——大题（Layer）行与其下的练习组（Unit）行都是标准胶囊卡片（`.capsule-card`，56px，块级充满宽度）：

- 大题行：左侧展开箭头 + 名称（600），右侧「N 组 · M 题」（13px 次要色）；整行可点击展开/收起，悬停边框与文字变品牌色。
- 练习组行：缩进 24px 排在所属大题之下，左侧名称，右侧题数，最右是**嵌在胶囊内的**「开始练习」主按钮（36px 高胶囊按钮，品牌色填充；整行本身不可点击，不做悬停上浮）。

高度属于组件标准：同类单行胶囊卡片沿用 `--capsule-height`；包含题型名称与数量的多行题型选择卡片不适用此高度，见 `button-spec.md`。

## 7. 字体和排版

### 7.1 字体系统

使用清晰的无衬线字体作为主要 UI 字体。

建议：

- 中文：Noto Sans SC / 系统中文无衬线。
- 日文 UI：Noto Sans JP。
- 英文与数字：Inter 或系统无衬线。

长篇日文阅读材料允许选择 Noto Serif JP，但普通 UI、选项、按钮及题目短句以无衬线为主。

### 7.2 字体层级

**标题字号梯度 H1–H6**（2026-11-16，用户指定 H1 = 38px，依次递减；Token 见 §13.1）：

| 层级 | 桌面 | 窄屏（≤720px） | 字重 | 用途 |
|---|---|---|---|---|
| H1 | **38px** | 30px | 700 | 页面主标题（每页一个 `h1`） |
| H2 | 30px | 26px | 700 | 品牌页/大区块标题 |
| H3 | 24px | 22px | 600–700 | 页面模块标题（如首页「专项练习」「历年试卷」、练习结果「逐题复盘」） |
| H4 | 20px | 19px | 600 | 卡片标题、对话框标题、统计数字 |
| H5 | 17px | 17px | 600 | 小节标题、题目级标题 |
| H6 | 15px | 15px | 600 | 正文级小标题 |

规则：
- 未加样式的 `h1`–`h6` 默认取同号层级；组件按**角色**选用 Token（如页面内模块标题虽是 `h2` 元素，视觉用 H3），不得在组件里再写死标题字号。文档大纲（语义层级）与视觉层级可以不同，但不得为了字号而跳级或乱用标签。
- 窄屏只缩小 H1–H4，H5/H6 不变；H1 在 375px 宽度下 30px，9 个汉字的首页标题保持单行。
- 卡片内的标题（如登录卡片）若使用 `h1`，同样取 H1 尺寸。

**正文与辅助字号：**

| 类型 | 桌面参考尺寸 | 字重 |
|---|---|---|
| 页面主标题 | 见上表 H1 | 700 |
| 页面模块标题 | 见上表 H3 | 600–700 |
| 卡片标题 | 见上表 H4/H5 | 600 |
| 正文 | 15–16px | 400 |
| 辅助文本 | 13–14px | 400 |
| 小标签 | 12–13px | 500 |

避免在同一页面使用过多字重。

### 7.3 日语内容

练习页面必须优先考虑阅读舒适性。

- 正文字号建议 16–18px。
- 长篇读解行高建议 1.7–1.9。
- 保留日语原有标点、换行、下划线及 Ruby。
- 不因页面排版自动改写题目内容。
- 不为了追求紧凑而压缩长文章的阅读空间。

## 8. 圆角、边框与阴影

### 8.1 圆角体系

| 类型 | 建议值 |
|---|---|
| 输入框、题号导航 | 12px |
| 普通卡片 | 16px |
| 重点卡片 | 18–20px |
| 操作按钮、胶囊导航 | 999px |

圆角应根据组件角色使用，不要求所有元素都做成胶囊。

### 8.2 阴影规则

阴影只用于表达浮动层次。

- 普通内容卡片、胶囊卡片：`--shadow-card`（`0 6px 24px rgba(43,43,51,0.09)`）。卡片无边框时，**区分度完全靠这层阴影**，所以不再使用「极浅」阴影（2026-11-16 由 0.035 加深到 0.09，偏移与模糊同步增大）。
- 悬浮导航：同 `--shadow-card`。
- Hover 卡片：加强为 `--shadow-floating`（`0 12px 36px rgba(43,43,51,0.15)`）；该 Token 同时用于吸顶头部胶囊与 Popover，因此它们也随之变深。
- 层级约束：`--shadow-floating` 必须明显深于 `--shadow-card`，否则悬停反馈会比静止态更弱。
- 弹窗、Popover：使用 `--shadow-floating`。

避免使用多层重阴影和强烈的粉色投影；阴影一律为中性墨色。

## 9. 按钮和交互状态

### 9.1 操作按钮统一标准（2026-11-17）

完整标准见 [button-spec.md](button-spec.md)，作为用户端按钮尺寸、层级、状态与场景映射的唯一主题规范。

- 操作按钮统一胶囊圆角 `999px`；默认高 44px、字号 16px、字重 600、水平 padding 24px。
- Small 36px、Large 48px 仅按规定场景使用；同一操作区尺寸一致。
- 同一操作区最多一个深樱色主按钮；其余按次按钮或轻按钮处理。
- 题号、题型卡片、Tab、选项与音频控件沿用各自组件角色，不强行套用操作按钮。

### 9.2 次级操作与链接

- 次按钮统一白底、墨色字、1px 轻边框，尺寸与圆角同主按钮。
- 底部操作区的链接也使用对应按钮外观；说明段落中的跳转才用行内下划线链接。
- Disabled、Loading、Hover、Pressed 与 Focus-visible 必须齐全，规则见按钮主题规范。

### 9.3 动效

统一使用简短、平滑的过渡。

建议：

- 普通 Hover：120–180ms。
- 卡片上浮：1–2px。
- 状态切换：约 160–220ms。
- 尊重 `prefers-reduced-motion`。

不要使用持续循环的装饰动画。

### 9.4 选中和焦点状态

- 导航 Active：浅樱底色。
- 分段选择 Active：浅樱或深樱，依据组件层级。
- 页面级 Tab：保持清晰、扁平的下划线样式。
- 表单 Focus：具有足够对比度的焦点轮廓。
- 答题选项的已选中、正确、错误状态必须有独立的语义表达。

导航胶囊的 Active 样式不应直接套用到所有 Tab 和题目选项上。

### 9.5 选择器（Select）与 Popover

下拉选择统一使用自研 Select 组件，规格见 [`select-spec.md`](select-spec.md)（Trigger 44/36px、Popover 16px 圆角、选中浅樱 + 对勾、Popover 与 Modal 区分、避让视口且不被父容器裁剪）。不再使用原生 `<select>` 作为用户可见控件。

## 10. 响应式设计

### Desktop（≥1024px）

- 居中固定宽度胶囊导航。
- 四个专项入口并排。
- 历年试卷可采用三列。
- 充分利用留白和横向空间。

### Tablet（768–1023px）

- 专项入口调整为两列。
- 历年试卷根据空间调整为两列。
- 导航适当压缩，但保留完整可理解的入口。

### Mobile（小于768px）

- 页边距 16px。
- 首页标题缩小。
- 专项卡片根据可用宽度采用一列或两列。
- 恢复练习按钮保持易触达。
- 长篇阅读内容避免横向溢出。
- 固定音频播放器不能遮挡选项和提交按钮。

## 11. 无障碍与可用性

必须满足：

- 正文与背景有足够对比度，普通文字目标至少 WCAG AA 4.5:1。
- 键盘可以操作导航、卡片、按钮和选择项。
- 焦点状态可见。
- 操作反馈不能只通过颜色传达。
- 按钮和选项具有合理触控尺寸。
- 使用正确的 HTML 语义。
- 尊重系统减少动态效果偏好。
- 加载、空数据、错误及不可用状态有完整设计。

## 12. 品牌页与学习系统的差异

品牌页与学习系统共用设计 Token、字体、卡片和按钮。

但两者的视觉重点不同。

**品牌页 `/`：**

- 可以更大胆地展示品牌视觉。
- 允许适量日式抽象装饰。
- 更重视品牌价值、产品介绍和引导注册。
- 根据 ADR-0007 采用预渲染。

**学习首页 `/study`：**

- 视觉更加克制。
- 优先展示学习操作。
- 不使用大型营销 Hero。
- 不展示不必要的品牌宣传按钮。
- 以 SPA 交互为主。

## 13. Figma 和前端实施要求

Figma 必须提供以下组件状态：

- 主导航 Default / Hover / Active / Focus。
- 主要与次级按钮。
- 专项练习卡片 Default / Hover。
- 历年试卷卡片。
- 继续练习卡片。
- JLPT 等级选择器。
- 空状态、加载状态、错误状态。
- Desktop / Tablet / Mobile 示例。

前端应通过设计 Token 实现颜色、尺寸、圆角和阴影，不允许在各个组件中随意重复硬编码相同样式。

### 13.1 基准 Token（:root）

```css
:root {
  /* Brand */
  --color-bg: #FAF7F2;
  --color-surface: #FFFFFF;
  --color-ink: #2B2B33;
  --color-primary: #B94968;
  --color-primary-hover: #A53C5B;
  --color-primary-soft: #F6E8EC;

  /* Neutral */
  --color-text-secondary: #706B70;
  --color-text-muted: #88838A;
  --color-border: #E8E3DF;
  --color-surface-subtle: #F4F1ED;

  /* Radius */
  --radius-sm: 12px;
  --radius-card: 16px;
  --radius-lg: 20px;
  --radius-pill: 999px;

  /* Layout */
  --page-max-width: 1280px;
  --nav-width: 580px;
  --nav-height: 56px;
  --capsule-height: 56px; /* §6.5 月份胶囊卡片标准高度 */

  /* Heading scale (§7.2); ≤720px: h1 30 / h2 26 / h3 22 / h4 19 */
  --text-h1: 38px;
  --text-h2: 30px;
  --text-h3: 24px;
  --text-h4: 20px;
  --text-h5: 17px;
  --text-h6: 15px;

  /* Shadow */
  --shadow-card: 0 6px 24px rgba(43, 43, 51, 0.09);
  --shadow-floating: 0 12px 36px rgba(43, 43, 51, 0.15);

  /* Motion */
  --motion-fast: 160ms;
  --motion-normal: 220ms;
}
```

语义色（§2.3 要求的正确/错误/警示）与字号、间距 Token 不在上方清单中，但必须保留并继续 Token 化，起始值沿用现有实现：

| Token | 值 | 用途 |
|---|---|---|
| `--color-success` | `#2F7D4F` | 判对反馈 |
| `--color-danger` | `#C73E3A` | 判错与故障 |
| `--color-warning` | `#B98A1E` | 时间/待确认/警示 |

间距沿用 4px 基准（4/8/12/16/24/32/48/64），字号层级见 §7.2；音频 dock 高度等组件级变量保留在组件作用域定义。

重要交互组件应保留合理的可访问性。

## 14. 设计验收标准

- 顶部导航不再是传统的通栏菜单。
- 胶囊导航宽度受控，桌面端视觉居中。
- Logo、主导航和账户入口职责清晰。
- 页面没有过度依赖传统日本元素。
- 卡片层次柔和，不出现大量彩色边框。
- 四个科目入口清晰且易操作。
- 继续练习入口足够醒目。
- 学习首页在移除装饰元素后仍然完整可用。
- 移动端没有截断、遮挡和无法点击的问题。
- 所有视觉规则能够通过统一 Token 和组件复用实现。

**最终视觉原则：现代感来自比例、留白、排版和交互细节，而不是增加装饰。**
