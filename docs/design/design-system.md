# Design System v2 · 樱与墨 Sakura & Ink

> **2.0 权威视觉原则**。参考 `reference/v1/design-system.md` 的品牌经验，但 v1 曾使用的整块主色 Tab、广泛衬线字体和大量可按压卡片在 v2 已调整。配色方向已确认；断点、字阶等量化 token 是首版建议，实际页面截图验收后可修订。

## 视觉目标

日式文具的清爽、暖纸底色、墨色排版与少量樱花点缀，**更现代、非复古**。UI 是专注学习的工具，避免过多粉色、立体感、纸纹、渐变、浮夸装饰和重阴影。可考虑小面积富士山/樱花画面作为品牌插画，不做全屏背景干扰内容。主题色不超过必要语义层次不是“全站只能用三种 HEX”：成功、错误、警示等反馈必须有独立语义色。

## 色彩 Token（light，建议起始值）

| Token | 值 | 用途 |
|---|---|---|
| `--color-canvas` | `#FAF7F2` | 全局暖白画布 |
| `--color-paper` | `#FFFFFF` | 卡片/面板 |
| `--color-ink` | `#2B2B33` | 主文字 |
| `--color-muted` | `#7A7580` | 次级文字 |
| `--color-border` | `#E6E3E0` | 分隔与边界 |
| `--color-primary` | `#B94968` | 主动作、选中、关键点 |
| `--color-primary-strong` | `#93354F` | hover/强调文字 |
| `--color-primary-soft` | `#FBE3EA` | 轻量选中底色 |
| `--color-success` | `#2F7D4F` | 判对反馈 |
| `--color-danger` | `#C73E3A` | 判错与故障 |
| `--color-warning` | `#B98A1E` | 时间/待确认/警示 |

适配暗色需另定完整对比度安全色板，不准直接反相图片。原 v1 暖黑 `#1F1D23`/`#28262E` 可参考，但**不是**尚未确认的 v2 深色强制值。业务组件使用 tokens 而非散落 HEX。图表各科目颜色可作为数据可辨色，不能误用成功/错误色表示科目。

## 字体与文字层级

- **UI、短题、选项、解析、翻译**以易读的系统 sans（日文后备可 `Noto Sans JP`）为主。
- **长篇读解文章**可选择 `Noto Serif JP`，仅在具备实际阅读价值时使用；不要让所有题干、解析都套衬线。
- 阅读正文建议 `line-height: 1.7–1.9`，适当段落间距，保留日语原文全角字符、缩进、星号和下划线；不要批量 NFKC 正规化。
- 建议初始字阶：辅助 12、正文 14–16、题干 17–19、分区标题 20–24 px；必须检查日语字形和长选项的换行。
- `printed_number` 如 `01`、`1番`、`質問1` 是内容字段；不要由数组索引重建。

## 页面、网格和密度

- 顶部统一导航；PC-first 但无需侧栏。全局内容上限起始建议 **1180–1240px**（复用 v1 1180px 是候选，不是确定值），长阅读列另外限制合适行宽。
- 4px 基础间距倍数；建议 8/12/16/24/32，视觉层级优先依赖留白与字重，不依赖盒套盒。
- 主要按键建议 44–52px 高，触控目标不小于 44px；边角圆润但不做胶囊堆砌。建议 radius 8/12/16/20px。
- 轻立体用于**主按钮、可点选项和明确可操作卡片**；正文卡和统计内容大多扁平；按压位移可有但尊重系统减少动效。
- 内容区隔优先细分隔线；`--color-border`，少量软底；不叠双重边框和阴影。

## 关键组件规范

| 元件 | 2.0 规则 |
|---|---|
| 全局导航 | 顶部水平；活动项通过细线、字重或低干扰强调表达 |
| 页面级 Tab | **扁平文字 + 下划线**，不再使用 v1 实心樱红背景/压感阴影 |
| 小范围切换 | 允许低对比浅底 segmented control；别混同主导航 Tab |
| Primary CTA | 同一可视任务区只突出一项主行动；主按钮可以轻触感 |
| Secondary/Ghost | 不抢主行动；取消和返回低权重 |
| 题目选项 | 高度充足、字母/序号独立、选中与锁定明显；提交前不标正确/错误 |
| 即时反馈 | 少量成功/错误语义信号 + 中性解析内容；带文字与图标，不只靠颜色 |
| Badge | 状态标签少而清晰，不用彩色徽章填满界面 |
| 卡片 | 首页四学科入口可点；文章正文面板尽量扁平、没有多余阴影 |
| 音频播放器 | 底部固定，仅一处，正文和底部按钮预留 padding，窄屏紧凑 |
| 弹窗 | 不答题提交确认、会话替换提示、异常反馈；移动端可变底部抽屉 |

## 交互状态矩阵

- 任何可交互元素考虑 `rest / hover / focus-visible / selected / disabled / loading / error`，选项另有 `draft / submitted-correct / submitted-wrong / submitted-skipped`。
- 焦点必须可见；错误时用文字 + 图标；提示不要只以色相变化表达。
- 减少动态效果设置下删除非必要位移/淡入；网络保存等待不显示假“已保存”。
- 读解双栏是否使用由实际宽度决定：PC 宽屏文章/题目并列；窄屏单栏，不允许两个互相抢焦点的嵌套滚动区。

## 主题与插画边界

- 首期以 light 主题先完成一致性；dark 如实现则必须审查所有对比度、图片底色和听力面板状态。
- 日本动物主题头像：可采用 12 款基础动物、独立背景色、**无边框**，后续季节限定单独扩充；不因为头像装饰改变题目答题体验。头像资产由独立设计任务提供，本文不假装已落地。
- 视觉验收必须使用真实 N1 长文章、N5 看图题、N2 填空、移动端听力作答等场景，而不只审核静态 mockup。

## 与 1.0 的差异

v1 `design-system.md` 提供了具体 Sass tokens 与组件样式；2.0 不直接复制其 `.subject-tabs`、`.app-frame` 等 CSS 类名或 1.0 的季节动效策略。新组件按本规范新建，后续页面实测后再修订可量化参数。
