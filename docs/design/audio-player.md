# 听力播放器 UI 规范（Floating Audio Dock + Transcript Panel）

> **版本** v1.1 · 2026-11-17 · 设计体系：樱与墨 Modern Minimal（`design-system.md` v1.1）
> **范围**：桌面端。移动端专用播放器、严格模拟播放规则重定义、精听系统、AB 循环面板、AI 配音、波形可视化均不在本版范围（见 §13）。

## 1. 设计目标

播放器采用底部悬浮布局，与练习页面内容区域等宽。规范包含两部分：

1. **Floating Audio Dock**：音频播放与基础控制。
2. **Transcript Panel**：在播放器上方向上展开的听力原文区域。

参考音乐播放器歌词交互，但**不采用全屏播放器，也不允许自由拖动播放器**。

核心原则：

- 播放器醒目但不抢夺试题注意力。
- 与答题内容宽度一致。
- 不使用波形可视化。
- 播放器固定在视口底部；原文面板在播放器上方向上展开。
- 展开后不改变页面布局与文档高度；原文区域独立滚动。
- 音频播放与面板开合相互独立。
- 严格遵守听力原文的访问权限（§8，后端保障）。

## 2. 播放器布局

### 2.1 位置与尺寸

| 属性 | 规范 |
|---|---|
| 定位方式 | `position: fixed`，水平居中 |
| 宽度 | 桌面宽屏下比内容容器窄 100px（2026-11-17 用户调整）；窄视口跟随 `.container` 侧边距。复用 `--page-max-width`，不另设一套最大宽度 |
| 默认高度 | 80px |
| 距离视口底部 | 20px |
| 背景 | `--color-surface`（#FFFFFF） |
| 圆角 | 胶囊全圆角 999px（2026-11-17 用户调整，原 24px） |
| 边框 | 无（2026-11-17 用户调整，仅阴影；原 `1px solid var(--color-border)`） |
| 阴影 | `0 8px 32px rgba(43,43,51,0.10)` |

页面预留底部空间：dock 高度 + 20px + 安全区，防止遮挡题目或提交按钮。

### 2.2 结构（从左到右）

- **音频信息**：耳机图标 + 音频标题（如 `1番の音声`）+ 所属练习（如 `练习 · 组 1`）。
- **播放控制**：后退 5 秒 · 播放/暂停 · 前进 5 秒。主播放按钮为 48px 深樱色圆形。
- **进度控制**：线性进度条（4px 高、深樱已播、滑块约 14px）+ 当前时间/总时长（等宽数字）。不显示波形。
- **辅助操作**：倍速选择（Compact Select + Popover）、音量（Popover + 滑杆）、「原文」展开按钮（文字 + 图标组合，不只一个箭头）。

## 3. 听力原文展开交互

### 3.1 整体行为

点击「原文」后：面板在播放器上方向上展开；播放器保持原位；页面内容不位移、文档高度不变；播放进度不重置、音频保持原有播放/暂停状态。再次点击「原文」或收起按钮关闭。

不采用自由拖动窗口，不允许播放器在页面中移动。

### 3.2 展开结构

```text
┌──────────────────────────────────────────────┐
│ 听力原文                     跟随播放 [开关] │
│──────────────────────────────────────────────│
│ 女：すみません、この近くに……                 │
│ ▶当前播放段落（字体变深樱色）                 │
│ 男：はい、ありますよ。                       │
│ 女：ありがとうございます。                   │
│         ↑ 内容独立滚动 ↓                     │
├──────────────────────────────────────────────┤
│ 🎧 音频信息  ↶5  ▶  ↷5  ━●━━  时间  倍速 🔊 原文 │
└──────────────────────────────────────────────┘
```

### 3.3 原文面板尺寸（2026-11-17 优化轮修订）

| 属性 | 建议值 |
|---|---|
| 宽度 | 与播放器完全一致（同一浮动组件） |
| 默认高度 | 300px（最大 360px） |
| 阅读行宽 | 正文最大约 800px，面板内居中 |
| 背景 | 与播放器统一白色；与播放器之间仅一条浅色分割线 |
| 滚动 | `overflow-y: auto`，内部独立滚动 |

面板与播放器是**同一个浮动组件**：共用一组外圆角（面板顶部 20px、播放器底部胶囊）、统一白色背景与一层轻量阴影；面板向上展开、播放器始终在底部。面板实际高度受可用视口空间限制，顶部不得超出可视范围。**禁止因展开面板修改页面主体的高度、margin 或滚动位置。**

### 3.4 浮层层级

普通页面内容最下层；Dock 与 Panel 在其上；Modal/系统弹层最高（z-index：dock+panel 15 < modal 20 < popover 60）。展开时不显示全屏遮罩、不锁定页面滚动；面板遮挡试题时用户可立即收起，页面仍可正常滚动。

## 4. 原文内容显示

### 4.1 数据来源

继续使用 Canonical 数据：`Material`、`Material.cues`、`start_ms`、`end_ms`、对应 `MediaAsset`。不直接使用未清洗的原始 HTML。

原文文字完整保留：日语正文、说话人信息、标点、换行、经规范转换的富文本语义（经 RichText 白名单渲染）。

### 4.2 段落展示

每个 Cue 是一个独立可识别段落：段落文字、当前播放状态、必要时的说话人标签。**不显示时间范围数值**（2026-11-17 用户两次确认；时间戳仅用于高亮与点击定位，不出现在界面上）。当前播放段落使用浅樱背景 `--color-primary-soft`，文字保持墨色对比（不降低其他段落对比度、不使用聊天气泡布局）。**原文面板是阅读与定位工具，不是聊天界面**。

排版（桌面端）：面板标题 18px/600；日文正文 16px/400、行高 1.8；段落间距 12px；面板内左右留白 24px；不修改原始题目文本，完整保留日语原文、标点、说话人与换行。

## 5. 当前播放段落高亮

匹配规则：`start_ms <= currentTime < end_ms`。

- Active 状态：浅樱背景 `--color-primary-soft`，文字保持墨色（2026-11-17 优化轮恢复背景样式，覆盖当日早前「仅变色」方案）；时间标签不再显示（用户确认）；不使用闪烁/脉冲动画。
- 非当前段落保持正常对比度，不过度淡化。
- 无法匹配时不强行高亮最近段落、不猜测缺失时间区间。

## 6. 跟随播放

面板提供「跟随播放」开关，默认开启，使用 Token 风格 Switch（非 Checkbox）。播放进入新 Cue 时平滑滚动当前段落到面板适当位置（尊重 `prefers-reduced-motion`）。用户主动滚动面板时**暂停自动跟随**（不与用户争夺滚动），音频继续、当前 Cue 仍高亮；重新开启 Switch 恢复。不强行把用户拉回当前段落。关闭面板不停止音频，展开面板不重置进度。

## 7. 点击原文段落定位

普通练习允许定位：点击 Cue → 定位到 `start_ms` 并开始播放，同步高亮与进度。练习模式禁止跳转时段落不提供可操作定位。

时间轴异常处理：时间戳缺失、非法或无法可靠映射时——仍展示合法原文文字、禁用该段落点击定位、不人为补充时间戳、不显示为正常可点击状态。整份材料无可靠 Cue 时退化为普通可滚动原文。

## 8. 原文访问权限（必须由后端保障）

听力原文可能直接包含答题线索，不能仅靠前端隐藏按钮：

| 模式 | 允许查看时机 |
|---|---|
| 普通练习 · 即时反馈 | 该 Unit 完整提交成功后 |
| 普通练习 · 统一反馈 | 整次练习正式结束后 |
| 严格模拟 | 不默认开放；按经确认的模考规则由服务端控制 |

- 权限不足时原文按钮可隐藏或显示锁定状态；API 不得提前返回受限制原文。
- 不得把私有原文预加载到浏览器后仅靠 CSS 隐藏。
- 实现上与 feedback 端点同一权限门控（`GET /api/practice/sessions/{sid}/units/{suid}/transcript`，未授权统一 409/404，无泄漏）。

## 9. 动效与交互状态

- 展开：向上、淡入 + 轻微位移、200–240ms；播放器不移动。
- 收起：向播放器方向收起；不影响音频播放与页面滚动位置。
- 必须覆盖状态：原文加载中 / 为空 / 暂不可查看 / 加载失败 / 当前段落高亮 / 跟随开关 / Cue 无时间戳 / 音频暂停或结束。
- 尊重 `prefers-reduced-motion`。

## 10. 组件结构

```text
AudioDock/
├── AudioDock.tsx            # 编排 + <audio> 单实例
├── AudioInfo.tsx
├── PlaybackControls.tsx
├── AudioProgress.tsx
├── PlaybackSpeedSelect.tsx
├── VolumeControl.tsx
├── TranscriptToggle.tsx     # 「原文」入口（锁定/展开态）
├── TranscriptPanel.tsx      # 面板 + 独立滚动 + 跟随逻辑
├── TranscriptCueItem.tsx
└── useAudioPlayer.ts        # 共享音频控制实例（唯一 <audio>）
```

播放器状态：`audioAssetId(src)`、`currentTime`、`duration`、`isPlaying`、`playbackRate`、`volume`、`isLoading`、`error`。原文 UI 状态：`isTranscriptExpanded`、`isFollowEnabled`、`activeCueId`、`transcriptLoading`、`transcriptError`。**展开/收起原文不得重建 Audio 实例或重新加载音频**（面板与 `<audio>` 同树、音频元素常驻）。

## 11. 无障碍要求

- 「原文」按钮暴露正确 `aria-expanded`、关联面板（`aria-controls`）、键盘可开合、Esc 可收起。
- 展开时不强制移动焦点；面板为非模态区域，不做 Modal 焦点锁定。
- 可点击 Cue 支持键盘操作；Active 除颜色变化外带 `aria-current`，不单靠颜色。
- 滚动区域可键盘访问；尊重 `prefers-reduced-motion`。

## 12. 开发与交付要求

1. 复用现有播放逻辑，不因 UI 改版重写音频数据处理；不修改 Canonical Schema。
2. 不放宽后端原文访问权限；提交前 0 泄漏。
3. 真实测试结果；更新开发日志与 `progress.md`；记录 Git Commit。

### 验收要点

播放器与内容容器等宽且固定视口底部；面板向上展开且页面高度/滚动位置不变；音频不因面板开合重播；面板独立滚动；当前 Cue 正确高亮；跟随可开关；点击 Cue 正确定位（仅限允许模式）；无效 Cue 不错误定位；受限制原文不经 API 提前泄漏；收起后所有播放控制正常；键盘操作正常。

## 13. 明确不做

播放器自由拖动、面板自由缩放、全屏歌词模式、波形可视化、AI 音频重制、完整精听训练系统、复杂 AB 循环面板、移动端专用播放器、未经确认的严格模拟播放规则。
