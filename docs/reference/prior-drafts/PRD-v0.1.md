# JLPT GO 2.0｜产品需求规格（PRD）

> 版本：v0.1 · 2026-11-15  
> 状态：**讨论稿，尚未基线定稿**  
> 适用范围：JLPT GO 2.0（全新独立项目）  
> 本文只定义产品需求与体验规则，**不授权修改现有代码、数据库或生产环境**。

## 文档状态与决策用语

- **[已确认]**：用户在此前产品讨论中已经明确选择或认可。
- **[建议]**：基于讨论提出、等待产品确认的建议，不应直接作为开发硬规则。
- **[待确认]**：存在多个合理方案，尚未决定。
- **[待验证]**：需要结合真实题库、数据结构、实际行为或技术实验核实。

本文中未标记为“已确认”的功能规则，不应在后续架构设计中被默认为最终需求。

## 1. 项目定位与边界

### 1.1 背景

[已确认] 现有 JLPT GO 1.0 已上线供少量朋友使用；用户决定启动全新的 JLPT GO 2.0 项目。**1.0 继续运行，不在旧代码上开展大规模重构；2.0 独立设计、独立开发。**

[建议] 1.0 仅进行必要安全、故障和服务维护；2.0 使用独立代码库、独立数据库、隔离部署环境。上线前再设计迁移和切换方案。

### 1.2 产品定位

[已确认] 以 JLPT 历年试卷和真题分类练习为核心，服务有明确备考目标、希望高效率刷题与复盘的用户。**PC 优先，同时保障移动端基本体验**。不以打卡、排行榜、连续签到等游戏化机制为核心。

### 1.3 设计目标

1. 从首页到开始练习，操作尽量少。
2. 在准确呈现真实 JLPT 题型的前提下，统一答题与反馈规则。
3. 用历史作答驱动智能随机选题，提高新题覆盖率并复习薄弱项。
4. 完整模拟与自由练习严格区分，成绩口径清晰。
5. 学习数据应支持下一步行动，不堆砌装饰性指标。
6. 2.0 的模型适合未来接入更多等级、年份和经过授权的题目资源。

### 1.4 非目标

- 本轮不设计或实现 AI 精读。该功能只是未来方向，未形成需求。
- 暂不以 AI 自动推荐每日学习计划、记忆曲线、积分排行榜为核心。
- 暂不以多题型手动配额的随机练习为核心。
- 不将旧版的所有页面或技术实现逐项平移到新版。
- 支付、自动续费、推广官网、国际化、复杂 AI 解析和造句等均属于**后续独立规划**，不因其存在于旧想法中就自动进入 2.0 首期。

## 2. 用户与关键场景

| 场景 | 用户任务 | 理想结果 |
|---|---|---|
| G01 | 想快速刷 N2 某类文法题 | 选题型和数量后立即开始 |
| G02 | 想查找 2024 年 7 月 N2 的某篇文章 | 打开试卷→科目→大题→文章，直接练习 |
| G03 | 想严格模拟一整场考试 | 进入独立模考流程，按考试规则完成并查看成绩 |
| G04 | 做题中断后返回 | 恢复原题、原答案、原进度 |
| G05 | 对某篇文章不确定，跳过几题 | 可以提交，并明确标记未答 |
| G06 | 想知道哪些题仍然做错 | 进入最近仍错筛选，直接复习 |
| G07 | 想继续新题，但兼顾旧错题 | 智能随机新题优先，留出复习配额 |
| G08 | 想找某次练习的解析 | 在练习历史中打开原始记录和复盘 |

## 3. 信息架构与导航

### 3.1 全局导航

[已确认] 页面顶部横向主导航，主要入口：

`首页`｜`专项练习`｜`历年试卷`｜`我的学习`

右上角：头像 / 账户与必要设置。**不使用全站侧边栏作为主导航**。

### 3.2 首页

[已确认]

- 无大面积欢迎 Hero、无首页 Tab、无统计仪表盘堆叠。
- 最重要的四个专项入口：**文字词汇、文法、读解、听力**。
- 有未完成练习时，在四个入口**上方**出现精简的「继续上次练习」；没有就隐藏。
- 保留简洁的「历年试卷」入口。
- 原教材 / 基础练习类内容收敛成次级入口「强化练习」，不在首页展示大量重复任务卡。

[建议] 考试倒计时为次要小信息；只有历史数据足够且确有可行动建议时才显示个性化练习建议，空数据时隐藏。

### 3.3 我的学习

[建议] 三个扁平 Tab：`学习概览`｜`练习历史`｜`题目记录`。题目记录整合错题和收藏，不额外建立复杂的错题管理中心。

## 4. 题目结构与基础业务概念

### 4.1 业务层级

[建议] 规范化的内容层级：

`试卷 Exam → 科目 Section → 大题 Layer → 练习单元 Unit → 题目 Question → 选项 Option`

- **Exam**：一份年份、月份、等级明确的试卷。
- **Section**：文字词汇、文法、读解、听力等界面内容分类；**不直接等同于模考计时阶段**。
- **Layer**：真实试卷中的「問題1／問題2……」。
- **Unit**：完整展示、抽样与即时反馈的最小材料单元，可以是独立单题、一篇文章、一份图片材料或一段音频及关联问题。
- **Question**：最小作答与评分单位。
- **Option**：具体选项。

**重要**：[待确认] 上述层级是 2.0 新领域模型候选方案，尚未进入最终数据库设计。当前先将其作为业务概念，不预设必须一层对应一张表。

### 4.2 与真实题库的对应

[待验证] 已上传样本包括 `exams.json`、`questions.json`、`assets.json`：32 套 N2 试卷、608 个大题、3,334 道题、1,147 条资源记录。

- 独立文字词汇 / 文法题：可单题作答，允许整大题连续练习。
- 文章中的文法：一篇文章可关联多个填空题。
- 读解：大题可能包含多篇文章，各篇关联 1 道或多道题。
- 信息检索：图片可能属于大题级公共材料。
- 听力：一段音频可关联一题或多题，部分材料含字幕或计时信息。

[待验证] 原始 `parent_id` 并不能无条件视为「真正共用材料」的标识；同大题的独立题可能拥有同一个父级值。导入规范应明确识别真正的 Unit。

## 5. 专项练习

### 5.1 配置

[已确认]

- 一次练习**只选择一个题型**，不再让用户多选题型并分别配置题数。
- 选择等级、具体题型、练习数量。
- 智能随机作为默认选题方向；复杂权重不暴露在基本配置界面。
- 即时反馈与统一反馈两种模式保留，但减少无效配置。

[建议] 数量按抽样单位表示：独立题按「道」，有公共材料的题按「篇／组／段」；显示预计关联的题数，不要求固定精确小题数。

### 5.2 智能随机选题

[已确认] 核心目标与原则：优先抽取**没做过、做得少、正确率低**的题；即使仍有大量新题，也留出约 **20%–30%** 给已做过但需巩固的题。

[建议] 第一版作为**软配额**：约 70%–80% 新题探索、20%–30% 复习巩固；候选不足时自动调整。

[建议] 复习池考虑：正式练习次数、有效作答正确率、最近一次有效正误、距最近练习的时间；优先避开刚完成的上一组，但不排除小题库中必要的重复。类别内应随机抽取，不是固定按得分排序。

[已确认] 共用材料题必须完整抽取，不拆开文章或音频组。独立题按单题抽取。

[待确认] 新题与复习题的精确权重、时间衰减、最近重复窗口、模拟成绩对随机权重的参与方式。实现前应通过多用户模拟数据调参。

### 5.3 「再练一组」

[建议] 默认沿用上次等级、题型、数量、反馈设置，重新抽样并尽量避免高度重复；允许返回配置页调整。

## 6. 统一答题和反馈规则

### 6.1 答题状态

[已确认] 明确区分「选择答案」与「正式提交答案」。提交前可修改；提交后本次答案锁定。统一反馈模式在整次练习结束前不展示正确答案。

| 情境 | 即时反馈 | 统一反馈 |
|---|---|---|
| 单个独立 Unit | 提交后显示正误、解析 | 如果本次只有此题，最终提交后显示 |
| 多个独立 Unit | 每题提交后反馈 | 本次所有 Unit 最终提交后反馈 |
| 共享材料 Unit | 一整个 Unit 提交后一起反馈 | 整次练习最终提交后反馈 |

[已确认] 所谓即时反馈是**完整 Unit 提交后反馈**，不是「选择一项立即公布答案」。避免一篇文章第一题的解析泄露同篇后面题目的答案。

[建议] 当模式选择不会产生实质差异（例如只练一个完整 Unit），隐藏反馈设置。

### 6.2 跳题与未作答

[已确认] **允许有未答题时提交**。

- 提交前显示未答题数，让用户选择「返回补答」或「确认提交」。
- 未答与答错是不同状态；未答不得自动进入错题本。
- 提交后本次答案锁定；若要再次练习，应产生新的正式作答记录。
- 即时反馈下，单个 Unit 允许部分未答后提交，视该 Unit 本次已完成；统一反馈下，在整次提交前可修改原选项。

### 6.3 数据与成绩口径

[已确认] 展示三种结果：正确、错误、未答。

[建议] 将两种数值区分：

- **本次得分率** = 正确题数 / 本次总题数，未答计入分母。
- **已作答正确率** = 正确回答次数 / 实际回答次数，未答不计入分母，主要用于长期历史表现。

示例：20 题，正确 12、错误 5、未答 3；本次得分率 60%，已作答正确率约 70.6%。UI 不应把两者都笼统称为「正确率」。

## 7. 历年试卷与完整模拟

### 7.1 历年试卷列表

[建议] 按等级、年份、月份定位试卷。每条试卷的主要操作是「查看试卷」，不要让所有行同时堆满模拟、专项、听力、统计按钮。

### 7.2 试卷详情

[已确认的方向]

- 试卷顶部有独立、明显但不夸张的「完整模拟考试」入口。
- 科目按扁平选项切换：文字词汇、文法、读解、听力。
- 按真实大题排列；大题展开后按实际题目或材料 Unit 显示。
- 点击单个材料／独立题，**直接进入练习**，不增加冗余模式选择页。

[建议] 展开状态、科目及滚动位置在短期返回时恢复；目录优先展示稳定编号、材料类型、题数和简单练习状态，不堆正确率。

[待确认] 对**多道互不依赖的独立题**，大题标题是否提供「练习本大题」作为连续练习入口：曾推荐同时支持整大题连续练习和单题进入，但用户尚未最终选择，不能写为已确认。

### 7.3 完整模拟

[已确认] 完整模拟为独立严格模式，答案不能在交卷前泄露；成绩与普通练习分开呈现和统计。

[建议] 保留考试说明、计时阶段、未答题、交卷确认、保存恢复、成绩和回顾；严格模式需与正常练习共用基础题目渲染，但不共用放宽的音频控制与答案可见性。

[待验证] 上传样本试卷 `duration` 为空；完整模拟时间规则、听力播放限制、断线处理、超时提交行为及正式分节须由准确规则与现有实现验证后定稿。

## 8. 练习结果、解析与复盘

[已确认]

| 类型 | 完成方式 | 结果界面 |
|---|---|---|
| 单题 | 当前页面完成 | 就地显示正误和解析，不跳冗余结果页 |
| 多道独立题 | 提交整次练习 | 简洁总结果与逐题复盘 |
| 语法 / 文章等成组题 | 按完整材料作答 | 总结果，按 Unit／材料组织复盘 |
| 严格模拟 | 交卷 | 独立考试成绩与试卷回顾 |

[已确认] 复盘保留用户当时的选择、正确答案、题目材料和解释；错误与未答分开展示。材料组内不可只展示错误选项而丢掉原文、图片或音频。

[建议] 多题复盘优先定位错误题；支持正确／错误／未答筛选和题号定位；结果页不要堆 AI 洞察、复杂雷达图与每日打卡信息。

## 9. 听力练习

[已确认] 普通听力相关练习在桌面与移动端均采用**底部固定播放器**；桌面可显示更多常用操作，移动端紧凑呈现且不能遮住提交按钮或选项；同时只保留一个主要播放器。

[建议] 普通训练支持必要的播放、暂停、进度与时间信息；可扩展速度、跳转和音量等能力，须确保移动端可用。不同听力练习间的恢复及切换行为需要明确定义。

[已确认的边界] 严格模拟不自动继承自由训练的无限拖动、倍速等能力；须遵循经验证的模拟考试规则。

[未纳入] AI 精读仍为未来方向。用户个人学习方式（逐段翻译→AI 校正→语法、生词批注）只是未来探索素材，不构成本期需求。听力「精听」高级流程也不在本 PRD 中擅自增加未确认操作。

## 10. 我的学习

### 10.1 定位

[已确认的产品方向] 「我的学习」不只是漂亮 Dashboard，而应服务：**发现薄弱项 → 进入针对性练习 → 再次验证**。

[建议] 三栏：学习概览、练习历史、题目记录。

### 10.2 推荐核心指标

[建议]

- 题库覆盖率：当前筛选范围内，**正式作答过的不同题目数** / 可练习题目总数；重复作答不增加覆盖数。
- 历史已作答正确率：统计范围、时间范围和来源明确；未答不算错答。
- 最近仍错题数：最近有效作答为错误的历史错题数量。
- 各题型表现：显示样本量，数据不足时不强行判定薄弱。
- 近期趋势：有足够样本时展示简洁比较。

[建议] 普通专项与严格模拟的成绩分开展示，不能混成一个看似精确的「综合能力分」。

### 10.3 错题策略 B

[已确认] **永久保留历史错题记录**，并支持：

- `曾经答错`：至少一次有效正式答错，历史保留。
- `最近仍错`：最近一次有效作答错误，优先复习。
- `最近已答对`：历史上错过，但最近一次有效作答正确，降低复习优先级。
- `最近未答`：本次跳过，不改变最近一次有效答对／答错结果，单独记录。

[已确认] 不因为答对一次就删除错题历史；但「最近仍错」与「最近已答对」要区分，不让所有历史错误永久占据待复习列表。

[建议] 两种行动入口：

1. **练习薄弱题型**：进入该题型智能随机（新题为主）。
2. **只复习最近仍错**：只从符合条件的历史错题抽取，不强制混入新题。

### 10.4 练习历史与收藏

[建议] 历史列表提供日期、练习名称、类型、题数、本次得分率及复盘入口。历史成绩作为不可静默改写的记录。

[建议] 收藏在「题目记录」中统一筛选或作为次级入口，不强制创建独立顶层导航项。

## 11. 账户、进度和可靠性

### 11.1 账户

[建议] 2.0 具备邮箱注册、登录、找回密码和最小个人资料；旧版账号迁移方案到上线准备期再决定。

### 11.2 进度保存

[已确认的现有能力 / 建议延续] 当前项目已经支持服务端进行中会话与恢复。2.0 应保留这一产品能力，但数据模型和实现可重新设计。

[建议]

- 进入新练习前，如旧练习进行中且会被替换，应明确提醒，不可无声覆盖。
- 已保存提示只能在服务端确认保存后展示；失败时给出重试与恢复操作。
- 刷新或临时离开后恢复题目顺序、已选答案和反馈锁定状态。
- 正式成绩与途中草稿严格区分，不将尚未提交的草稿当成完成记录。
- 「每个用户最多可有多少并行进行中会话」属于 2.0 架构决策，不能简单沿用旧版单活跃约束而不评估。

### 11.3 非功能质量

[建议]

- PC 优先，移动端不截断题目、选项与提交操作。
- 键盘焦点与选中状态清晰；反馈不仅依赖颜色；触控目标合理。
- 支持浅色 / 深色主题，减少突兀动效；尊重减少动态效果的系统偏好。
- 长篇日文、共用材料、表格 / 图片、听力播放器需要真实题目验证。
- 对含 HTML 的题干、解析和字幕做安全清洗；正式答案不在未授权阶段下发。

## 15. 核心验收场景（建议）

1. **独立题**：选择 N2 单题型，随机抽取指定数量；可选择、修改、提交、反馈、切换下一题；提交后不能修改该次答案。
2. **多题材料**：一篇读解含 3 题；即时反馈下只在该篇提交时一起揭晓；统一反馈下整次结束后才揭晓。
3. **跳题**：20 题里有 3 道未答，提交前提示 3 道，可返回补答或确认；历史中正确、错误、未答三态分明。
4. **智能随机**：新题充足时仍有约 20%–30% 已做题复习配额；抽题结果不在同一次出现重复 Question 或拆散 Unit。
5. **错题状态 B**：某题做错→仍错；再做对→最近已答对；再次遇到但跳过→最近有效正误仍为对，历史错题保留。
6. **完整模拟**：考试中无法从 API 或前端页面读取正确答案；结束后可回顾；普通训练成绩不覆盖模拟成绩。
7. **恢复**：中断后可重新进入并保留题目顺序、已选答案、反馈状态；保存失败不给错误的「已保存」提示。
8. **听力**：固定底部播放器不会覆盖移动端选项和提交；一段音频共用多个问题时表现一致。
9. **试卷目录**：可从某套试卷直达大题、文章或音频；返回后不丢失主要浏览位置。
10. **历史追溯**：题目解析后期被校正，不静默篡改以前的真实选择和提交时成绩。
