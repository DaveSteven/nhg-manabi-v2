# JLPT GO 2.0 · M2 核心学习流程开发计划

**项目：** nhg-manabi-v2  
**状态：** 待实施  
**前置里程碑：** M1、M1.5、M1.6 已完成  
**实施范围：** FastAPI 作答引擎 → React 学习页面 → 端到端验收

---

## 一、开发目标

完成 JLPT GO 2.0 的第一条可用学习流程：

**选择试卷 → 选择大题或 Unit → 开始练习 → 选择答案 → 提交 → 查看解析与结果。**

要求：

- 使用现有 Canonical v2.0 数据模型。
- 复用现有 PostgreSQL Schema。
- 支持独立题和共享材料 Unit。
- 支持即时反馈与统一反馈。
- 支持练习自动保存及恢复。
- 保证正式答案不会提前泄漏。
- 保持 JLPT GO 1.0 独立运行。

不将全量题库内容审核作为 M2 的阻塞依赖。

## 二、M2.1 · FastAPI 作答引擎

### Task 01：开发前检查

1. 阅读根目录 `AGENTS.md`。
2. 阅读最新 `progress.md`、数据库规范及开发日志。
3. 检查 Git 工作区及已有代码。
4. 确认现有 SQLAlchemy 模型和 Alembic 版本。
5. 检查现有 Publisher 和 Content API，避免重复开发。

特别注意：

- 当前已有发布内容权限隔离。
- Draft 内容不允许通过公开 API 直接暴露。
- 现有样本尚未完成正式内容审核。
- 测试使用隔离数据库，禁止清空开发数据库中的实际 Staging 数据。

### Task 02：题库查询 API

提供以下能力：

| API（建议） | 功能 |
|---|---|
| `GET /api/exams` | 查询可用试卷 |
| `GET /api/exams/{exam_id}` | 获取试卷详情 |
| `GET /api/exams/{exam_id}/layers` | 获取大题目录 |
| `GET /api/units/{unit_id}` | 获取完整练习 Unit |

允许复用或扩展已有 API，不要求为了匹配示例路径而重复创建接口。

要求：

- 保留 Section、Layer、Unit 的正确层级。
- 支持 RichText v1。
- 支持多题共享文章、图片和音频。
- 返回正确的选项顺序和印刷题号。
- 不返回未经允许的正确答案与解析。
- 非当前发布版本不得通过普通公开接口访问。
- 为开发测试提供受保护的 Draft Preview，不放宽正式发布门槛。

### Task 03：最小用户身份边界

作答记录必须归属于可验证的用户身份。

本阶段可使用隔离测试环境中的测试用户，不要求立即完成邮箱注册、密码找回等完整功能。

但必须保证：

- `user_id` 由服务端认证上下文确定。
- 不信任客户端自行传入的 `user_id`。
- 只能读取和修改自己的会话。
- 测试身份机制不能误用于生产环境。
- 后续可以接入正式认证系统。

### Task 04：练习会话管理

使用现有：

- `study_sessions`
- `study_session_units`

实现：

- 创建普通练习会话。
- 固定抽中的 Unit 及顺序。
- 支持单 Unit 和多 Unit 练习。
- 获取当前进行中的练习。
- 恢复练习状态。
- 主动结束练习。
- 完成练习后保存结果。

**（ADR-0016 修订，2026-11-17）每个用户只保留一份可恢复的进行中普通/专项练习（单一最近进度）。** 创建新练习时同一事务把旧的进行中练习置 `abandoned` 再创建，无 409 冲突、无弹窗；创建失败整体回滚，旧练习保留。旧练习已提交答案与历史保留，未提交草稿不参与成绩；`GET /api/practice/sessions/current` 返回唯一可恢复练习；正常完成后保存正式结果，不再可恢复。不做多练习列表/清理。Quick Practice 与严格模考单名额不变。

Session Unit 必须绑定具体 `release_id`，为后续跨年份随机练习预留支持。

### Task 05：答案草稿管理

使用 `study_answer_drafts`。

实现：

- 保存单题选择。
- 修改尚未提交的答案。
- 清除尚未提交的选择。
- 查询当前草稿。
- 刷新后恢复草稿。
- 防止旧请求覆盖新数据。

要求使用版本号或等效乐观锁机制。

**选择答案不等于正式提交。**

### Task 06：Unit 正式提交

使用 `study_submitted_answers`。

实现：

- 提交完整 Unit。
- 支持 Unit 中多道 Question。
- 允许部分题目未答。
- 校验选项确实属于对应 Question。
- 服务端判题。
- 保存正式答案版本与判题结果。
- 提交成功后锁定本次 Unit。
- 重复提交必须幂等。

未答题必须保存为：

`chosen_option_id = NULL`  
`is_correct = NULL`

不能自动标记为错误。

### Task 07：反馈权限控制

支持两种普通练习模式。

**即时反馈：**

提交完整 Unit 后，可以查看该 Unit 的正确答案和解析。

未提交的其他 Unit 不应暴露答案。

**统一反馈：**

练习正式结束前，不展示正确答案和解析。

练习完成后，再统一返回结果。

**提交方式（2026-11-17 修订）：** 统一反馈会话期间只保存草稿；逐 Unit 提交接口对该模式返回 409 `end_mode_requires_final_submit`。整次练习通过 `POST /api/practice/sessions/{id}/submit` 一次性提交：请求体为最终答案全集（草稿仅用于刷新恢复），服务端在同一事务内锁定会话、判定所有未提交 Unit、写入正式答案并生成 `study_results`；任一答案非法则整体回滚。已完成会话重复提交返回已存结果（`idempotent=true`，不重判不重写）。仅 `practice` 模式的统一反馈会话可用，即时反馈会话返回 409 `final_submit_end_mode_only`。

答案权限必须由后端控制，不能依靠 React 隐藏字段。

### Task 08：练习结果

实现：

- 正确数量。
- 错误数量。
- 未答数量。
- 总题数。
- 本次得分率。
- 已作答正确率。
- 完成时间。
- 逐题结果与复盘数据。

满足：

`correct + wrong + skipped = total`

提前结束的练习可以保留已经正式提交的答案，但不得生成一份虚假的完整练习成绩。

完整模拟考试的计时、阶段切换与评分不在本阶段实现。

## 三、M2.2 · React 学习页面

### Task 09：前端基础工程

采用已确定的：

**React Router Framework Mode + SSG + SPA**

- 公开品牌页面使用静态预渲染。
- `/study` 及学习功能使用 SPA。
- FastAPI 继续提供业务 API。
- 不引入运行时 Node.js SSR 服务。

采用「樱与墨」设计规范。

正式开发前，应将混合渲染决策写入 ADR（现为 `ADR-0007`；原建议编号 0005、0006 已被审核机制与最小身份边界占用）。

### Task 10：试卷与题目页面

实现：

- 试卷列表。
- Section 切换。
- Layer 展开。
- Unit 列表。
- 单 Unit 练习入口。
- RichText 题目渲染。
- 共享材料展示。
- 选项选择和提交状态。

PC 优先，同时保证移动端正常操作。

### Task 11：答题交互

实现：

- 选择和修改答案。
- 自动保存。
- 恢复当前进度。
- 未答题提交确认。
- Unit 提交后锁定。
- 即时反馈。
- 统一反馈。
- 简洁结果和解析。

听力页面应正确读取 Canonical 音频及 Cue 数据。

第一版只需实现必要的音频播放能力，不在此阶段扩展完整的精听学习系统。

## 四、M2.3 · 联调及验收

使用已有 N2 样本，至少测试以下场景：

| 场景 | 验收结果 |
|---|---|
| 文字词汇单题 | 正常作答、提交、显示解析 |
| 文法問題9 | 1 Unit、5 Question、Slot 绑定正确 |
| 读解問題11 | 三篇文章各自独立成 Unit |
| 听力题 | 音频、字幕和题目关联正确 |
| 刷新浏览器 | 恢复会话及草稿 |
| 重复提交 | 不生成重复成绩 |
| 未答提交 | 与错误答案明确区分 |
| 统一反馈 | 完成前不泄漏答案 |
| 跨账号访问 | 不能访问别人的练习 |
| 内容版本更新 | 历史 Session 继续引用旧 Release |

真实题目尚未通过发布门槛时，应通过隔离测试库中的合成内容或受保护的 Draft Preview 验证，不允许为了通过验收而公开未经审核的内容。

## 五、Git 提交计划

建议分成以下提交：

1. `feat(api): implement content queries and practice sessions`
2. `feat(api): implement drafts, submission and feedback`
3. `feat(web): implement exam navigation and practice pages`
4. `test(e2e): validate first complete learning flow`

如果某项任务涉及数据库迁移，单独提交 Alembic Revision。

每个提交应具备对应测试和必要文档更新。

## 六、开发纪律

每次开发任务结束，必须：

- 执行实际测试。
- 记录测试结果和未完成事项。
- 新增开发日志。
- 更新 `docs/development/progress.md`。
- 如有新的重大架构决策，建立 ADR。
- 记录 Git Commit。
- 保证旧版项目不受影响。

不得虚报测试通过，不得自动发布未审核题目，不得用开发模式绕过生产权限控制。

## 七、M2 完成标准

M2 不以完成全部后端 API 或全部前端页面作为目标。

**完成标准是：开发测试环境中能够真正打开一套 N2 试卷，选择 Unit，完成作答、保存、提交、判题和解析展示，并且刷新后能够正确恢复。**

达到这一目标后，进入下一阶段：

- 专项智能随机练习。
- 错题与历史记录。
- 题目复盘。
- 完整模拟考试。
- 正式用户认证和账户体系完善。
- 品牌官网内容与 SEO 建设。
