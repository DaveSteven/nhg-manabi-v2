## 2. 阶段与步骤

### 阶段 A：准备（不影响 V1，可提前做）
1. ⚠ 确定 D1–D7；在生产建立 v2 独立的数据库与服务（与 V1 隔离），配置 `.env`（强口令）、`APP_BASE_URL`、邮件三项、`PUBLISH_POLICY`，**生产必须 `APP_ENV=production`，不得设置 `AUTH_MODE=dev_test`**。
2. ⚠ 传输 `data/v2-media`，核对数量/大小/SHA-256；只读挂载。
3. 用 `develop` 的某个已审核 commit 构建镜像（记录 commit ID）。预发布环境按本节顺序先完整演练一遍，包含回滚。
4. 在生产库做版本化 `pg_dump` 并验证可恢复（此时库为空，也要留空库基线）。

### 阶段 B：部署 v2 空站（V1 仍是唯一对外入口）
5. ⚠ `alembic upgrade head`（0001→0020）。检查：迁移版本为 `0020_supplementary_exams`，`SELECT 1` 可用。
6. ⚠ 导入真实内容：`python -m app.importer data/normalized_v2`（108 个包 → 105 套已发布真题，`PUBLISH_POLICY=auto` 即发布）。核对：已发布 105、`mojitest` 题映射 10647。
7. ⚠ 导入扩展练习内容：用 `python -m app.v1_book_convert --v1-url <只读> --out <目录>` 生成 362 个包后 `python -m app.importer <目录>`。核对：`supplementary` 目录 362 课、3618 题、隐藏 Unit 0。
8. ⚠ 创建管理员（D5）。健康检查、登录页、真题列表、一套真题与一课扩展练习的完整作答（用测试账号，结束后删除或标记）。
9. 此时 **不开放** v2 给真实用户。

### 阶段 C：冻结 V1 并迁移用户数据（有停机窗口）
10. ⚠ 通知用户并冻结 V1：停止注册、改密、作答（建议只读页或维护页；不改 V1 数据，不改其代理规则以外的东西，具体方式由用户定）。记录冻结时间。
11. 在 V1 库做一次备份（只读操作，不改 V1）。
12. ⚠ 用户导入：`python -m app.v1_user_import --v1-url <只读>` 先 dry-run 核对（总数 7、无邮箱 7、跳过 0），再加 `--apply`。
13. ⚠ 教材作答：`python -m app.v1_answer_import --v1-url <只读>` dry-run 核对（应与阶段 C 冻结后的最新数据吻合：0 跳过、0 改判），再 `--apply`。
14. ⚠ 真题作答：`python -m app.v1_answer_import --kind exam --raw-dir data/samples --v1-url <只读>` dry-run → `--apply`。核对跳过数（预期仅 Unit 不可练习的少量）、改判为 0。
15. 抽样核对：用一个已导入用户（管理端重置密码得到临时口令，**让用户本人收到并尽快改**）验证：用 V1 用户名登录成功、旧口令登录成功并升级哈希（不能登录则视为失败）、「我的学习」覆盖率与仍错数合理、扩展练习课程进度显示。管理端「用户管理」能看到 7 个用户。
16. 若 dry-run 与 apply 的数字不吻合，或任一核对失败：**停止，不开放 v2**，回到阶段 B 修复，必要时回滚（见 §3）。

### 阶段 D：切换与观察
17. ⚠ 切换入口：把用户引导到 v2 地址（方式由 D4 定；不改 V1 服务器上的代理/数据，除非用户单独授权）。
18. 观察 24–72 小时：登录失败率、API 5xx、迁移用户的首次登录、邮件送达（若有新注册）、管理端 Dashboard。V1 保持只读以备查。
19. 观察期满且验收完成后，**由用户明确确认**，才把对应 `develop` 提交合并到 `main`（AGENTS：`main` 只代表已成功上线）。上线失败/回滚时不合并 `main`。

## 3. 回滚

| 阶段 | 失败时的做法 |
|---|---|
| A、B | v2 是独立的新环境：销毁或回滚到阶段 A 第 4 步的空库备份即可，V1 完全不受影响 |
| C（导入后发现数据问题） | 不开放 v2；用阶段 A/B 的备份恢复 v2 库，修复脚本或数据后重来（导入脚本幂等，但「恢复备份再重导」最干净）；V1 解冻，恢复原状 |
| D（切换后严重问题） | 把入口切回 V1 并解冻 V1。注意：切换后在 v2 产生的新数据不会回写 V1，需要事后单独处理（用户决定放弃还是补迁） |

迁移 0019/0020 的 downgrade 在存在无邮箱用户或扩展课时会拒绝执行（避免丢数据）；回滚用「恢复备份」，不要靠 downgrade。

## 4. 已知风险（带到上线评审）

1. 生产环境、HTTPS、邮件、媒体上传均未实际演练；`deployment.md` 仍写「尚未部署」。
2. 3618 道扩展题和真题答案均为 `unverified`、扩展题无解析；`auto` 策略直接对用户开放。
3. 7 个 V1 用户都没有邮箱：忘记密码只能管理员重置；未做绑定邮箱和自助改用户名入口。
4. V1 与 v2 并行/冻结窗口内的口令、作答不同步；V1 还在增长（教材作答已由 448 增至 538），必须在冻结后重跑 dry-run 取最终数字。
5. 导入的作答计入管理端学习活跃/作答统计；真题作答不进「练习历史」。
6. 未做 IP 级限流（ADR-0011 已知风险）；未做移动端与跨浏览器验收；严格模考的时间/音频规则仍待真实验收。
7. 页面标题等文案细节、扩展练习「再练一课/错题复习」未做。
