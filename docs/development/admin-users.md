# 管理端 · 用户管理（P0–P2）

接口 `GET /api/admin/users`、`GET /api/admin/users/{id}`、`POST /api/admin/users/{id}/disable|enable`（均需管理员会话）。实现：`backend/app/api/admin_users.py`、`apps/admin/src/features/users`。口径与 Dashboard（[admin-dashboard.md](admin-dashboard.md)）共用同一套定义，后端为唯一实现。

## 口径

- 日期统一 Asia/Tokyo；「近 7 天」含今天。
- 有效学习 = `study_submitted_answers` 中 `chosen_option_id` 非空的正式作答（草稿、skip、浏览不计）；同一天多次只算一个活跃日。
- 活跃状态（运营分类，与账号状态独立），按距最近一次有效学习日的东京日数 n：`尚未开始` 从未学习；`活跃` n≤6；`近期未活跃` 7≤n≤30；`长期沉默` n≥31。
- 账号状态：正常 / 已禁用 / 未验证邮箱，独立筛选。
- 最近访问：`user_visit_days` 的最近日期（仅日期）；无记录显示 `—`，绝不使用 `last_login_at` 代替。
- 列表包含**全部账号**（含禁用/未验证，便于管理）；顶部三项指标沿用 Dashboard「有效用户」口径（已验证、未禁用、不在 `DASHBOARD_EXCLUDE_EMAILS`），其中「近 7 天学习活跃用户」与 Dashboard 7 天 `active_learners` 一致（测试覆盖）；「尚未开始」= 有效用户中从未正式作答。注意这与 Dashboard 提醒「新注册未创建会话」口径不同。
- 搜索：昵称/邮箱不区分大小写子串匹配，`%`/`_` 按字面处理；排序白名单：注册时间、最近学习（无学习者排最后）、近 7 天作答；每页 20，最大 100。

## 详情

基本资料、四项学习指标（累计作答、累计完成练习、近 30 天活跃天数/作答）、30 天每日作答折线、功能使用（沿用 Dashboard 互斥分类，累计开始/完成）、科目分布（正式作答题次）、最近 10 条练习历史（复用「我的学习」历史口径：已完成/提前结束且有作答，完成的模考）、最近 10 条账号操作记录。响应不含口令哈希、令牌。

## 账号启用/禁用

- 前端二次确认，可填原因（≤500 字，选填）；仅 super_admin（现有管理员）可操作。
- 禁用：同一事务内置 `disabled_at`、撤销该用户全部学生会话、写审计日志；学习历史完整保留。重复禁用/启用返回 409（`already_disabled` / `not_disabled`），未知用户 404。
- 启用：清除 `disabled_at`，并重置登录失败计数与锁定。
- 审计：Alembic 0018 `admin_audit_logs`（仅追加，管理员身份由服务端写入，action 限 `user_disable`/`user_enable`）。

## 暂未做 / 取舍

- 「跳转只读结果详情」未做：管理端目前没有查看他人逐题答案的接口，需单独评审隐私边界；最近练习只列汇总。
- 头像：管理端无学生端头像资源，使用首字母占位。
- 不做批量操作、删除、群发邮件、画像标签。
- 访问数据自采集起点起才有，旧用户可能全部显示 `—`。
