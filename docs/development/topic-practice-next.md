# 专项练习：下一阶段实施拆分

日期：2026-11-17。状态：阶段 1–4 首版已实现（见 `docs/devlog/2026-11-17-topic-practice.md`），真实浏览器验收待用户；沿用现有已确认规则，未新增架构决策。

## 当前缺口与复用范围

顶部专项与首页四科仍为占位，无配置路由。普通会话创建接口要求明确的 release_id/unit_id 列表，无题型候选池或智能抽样接口。user_question_progress 目前只有表定义。

复用普通 practice 的草稿保存恢复（ADR-0016：单一最近进度，新开始即把旧进行中练习置 abandoned）、Unit 提交、反馈权限与结果页；quick_practice 独立名额及轻量交互保持现有 ADR-0014 规则。

## 实施顺序

| 阶段 | 交付 | 验收重点 |
|---|---|---|
| 1. 题型目录 | 等级、学科、Canonical 题型与真实可用 Unit 数量 | 核对跨年题型映射；不能把問題序号当题型；只计当前可用发布内容 |
| 2. 智能抽样 | 服务端按等级、单一题型和数量创建跨卷普通会话 | 完整 Unit 不拆分、不重复；每组绑定自己的 release；不向前端泄漏答案 |
| 3. 配置与入口 | 配置页、顶部专项、首页四科预选学科 | 数量按题/篇/组显示；超限提示；已有会话继续或替换；即时/统一反馈 |
| 4. 全流程 | 作答、恢复、结果及再练一组 | 刷新恢复草稿；再练复用配置重新抽题；quick 与专项互不占名额 |

默认新题占约 70–80%，复习占约 20–30%，候选不足弹性调整。复习权重依据真实正式作答历史，不用随机数伪造薄弱程度。具体权重参数、历史派生查询或缓存实现方式在开发时记录取舍，不在本文擅自锁定。

## 开发前测试与验收清单

- 题型/等级过滤、空候选池、数量超限与候选不足的软配额调整。
- 新用户无历史、历史全已练、跨卷多 Unit、同组多题完整性与去重。
- skip 不算错、不覆盖最近有效正误；草稿不计正式历史；quick 已提交记录可作为真实作答历史。
- 单一最近进度（ADR-0016）：新开始事务内 abandon 旧进行中会话并保留其已提交答案、草稿不计成绩、创建失败不丢旧练习、并发开始只剩一个进行中、完成后清除可恢复状态且结果保留、跨用户隔离、Quick/模考槽位不受影响。
- 即时反馈按 Unit 解锁、统一反馈完成前无答案或听力原文泄漏。
- 新 release 不影响已有 Session 的旧版本；跨账号不能读取会话或成绩。
- 前后端相关测试、类型检查与构建；真实浏览器验证四科入口、多组练习、刷新恢复、提交和结果。

测试先补用例再实现；如改变 Schema，新增迁移并执行真实 PostgreSQL 升级/约束/回滚验证。尚未执行以上专项测试，不可据此宣称功能已完成。

## 范围与后续

本阶段不扩展严格模拟、AI 功能或支付。专项闭环之后补错题本、学习历史及统计。开发完成不自动推送、部署或合并 main。

## 首版实现记录（2026-11-17）

- 接口：`GET /api/topic-practice/types?level=`（真实题型目录与数量，需登录）、`POST /api/topic-practice/sessions`（服务端抽样并复用普通 practice 会话事务；`replace_active` 原子替换）。会话 `config.topic` 保存等级/题型/数量，供「再练一组」复用配置。
- 抽样参数（可调，非产品规则）：复习占比 25%，其余新题；任一池不足由另一池补足；复习权重 = 0.2 + 2×平滑最近答错率 + 0.7×久未练习(上限 30 天) + 0.5/(1+练习次数)，加权无放回抽样保持随机。历史来自正式提交（practice + quick_practice），草稿不计，未答不覆盖最近有效正误；每次请求现算，未建缓存/物化（`user_question_progress` 仍未接入）。
- 前端：`/study/practice` 配置页（学科下划线 Tab → 题型 → 数量 → 反馈方式），顶栏「专项」与首页四科入口接通；（ADR-0016：无冲突弹窗，开始即创建并替换旧进行中练习）；结果页「再练一组」。
- 未做/待办：`user_question_progress` 缓存、「只复习最近仍错」独立入口、同题型邻近重复规避、跨卷 Unit 的来源展示、真实浏览器与响应式验收。
