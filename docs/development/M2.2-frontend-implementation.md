## 1. 开工核实与结论

### 1.1 已存在的后端能力

| 能力 | 现有端点 | 前端用途 |
|---|---|---|
| 已发布试卷列表 | `GET /api/exams` | 试卷目录 |

## 2. 技术与目录约束

采用 ADR-0007 已确认的 **React Router Framework Mode + SSG + SPA**：

- React + TypeScript；`ssr: false`。
- 样式统一使用 SCSS；组件局部样式优先采用 `.module.scss`，设计 token、reset 和跨页面基础样式由全局 `.scss` 入口承载。新增或修改业务样式不再写入普通 `.css` 文件。
- `/`、`/features`、已批准的 JLPT/指南公开内容由 `prerender` 生成静态 HTML。
- `/study` 及全部学习路由作为 SPA；不运行 Node.js SSR 服务。
- FastAPI 是业务和权限事实源；PostgreSQL 与现有后端不重写。
- 品牌页不得在构建期注入用户身份、私有题目、答案或解析。
- 静态服务必须区分预渲染 HTML 与 `__spa-fallback.html`，无效公开路由返回真实 404。

建议结构：

```text
apps/web/
├── app/
│   ├── routes/                 # SSG 品牌页与 /study SPA 路由
│   ├── features/catalog/       # 试卷、Section、Layer、Unit 目录
│   ├── features/practice/      # Session、草稿、提交、反馈、结果
│   ├── features/content/       # Canonical Unit/RichText/媒体 renderer
│   ├── components/             # 通用无业务组件
│   ├── api/                    # DTO、运行时校验、HTTP adapter、错误映射
│   └── styles/                 # “樱与墨” SCSS tokens 与全局样式入口
├── public/
├── react-router.config.ts
└── vite.config.ts
```

API DTO 与页面 view model 分层；页面不直接依赖数据库字段或旧版 `dataType`、`parent_id`。服务端正式状态优先，本地缓存仅用于待重试草稿和可丢失 UI 状态。

## 3. 路由与页面交付

为统一 `frontend-spec.md` 与 `page-structure.md` 中曾出现的 `/home`、`/exams`、`/practice` 建议路径，M2.2 以 ADR-0007 的 `/study` 命名空间为准：

| 路由 | 模式 | 内容 |
|---|---|---|
| `/` | SSG | 最小品牌首页；主要正文、title、description、canonical 均在初始 HTML |
| `/study` | SPA | 学习首页：四学科入口、继续上次练习、历年试卷入口 |
| `/study/exams` | SPA | 已发布试卷目录；无页内筛选，等级跟随备考等级，按年份分行的月份胶囊（2026-11-16） |
| `/study/exams/:examId` | SPA | Section 下划线 Tab、Layer 展开、Unit 列表 |
| `/study/practice/:sessionId` | SPA | Unit 材料、题目、选项、保存、提交、反馈 |
| `/study/practice/:sessionId/results` | SPA | 完整 Session 的简洁结果与逐题复盘 |

顶栏保持：首页、专项练习、历年试卷、我的学习。M2.2 尚未实现的入口显示明确的“暂未开放”状态，不伪造数据，也不扩展大 Hero、全局侧边栏或复杂游戏化模块。

## 4. 学习首页与试卷目录

### 4.1 学习首页

- 四科（文字词汇、文法、读解、听力）是第一视觉焦点。
- 并行请求试卷目录与 `sessions/current`；当前 Session 为 200 时显示继续入口，404 表示没有活跃练习，不作为错误提示。
- 恢复必须使用 Session 中固定的 `(release_id, unit_id)`，不得改用试卷当前 Release。
- 网络失败、未认证、空目录和没有活跃练习是不同状态。

### 4.2 试卷与 Unit 目录

- 试卷列表以真实 `level/year/month/title` 展示，不硬编码只有 7 月/12 月。
- 试卷详情按 `sections.position`、`layers.position`、`units.position` 排序；显示服务端 `printed_number`/label，不用数组索引重建。
- Section 使用页面级下划线 Tab；Layer 可展开；同一 Layer 内仍按真实 Unit 分组，不能自行合并共享材料。
- 单 Unit 入口调用 `POST /api/practice/sessions`；409 `active_session_exists` 时提供“继续旧练习”或“结束旧练习后再开始”，不静默替换。
- Draft、blocked、非当前发布内容不能通过学生端目录或直接 URL 显示。

## 5. Canonical Unit 与 RichText renderer

### 5.1 中性渲染模型

前端 adapter 将 API Unit 转为以下职责清晰的模型：

- Unit：稳定 `release_id/id/kind/position/label/slot_ids`。
- Material：文本、A/B 文、图片、音频、字幕/时间 cue 或组合。
- Question：稳定 ID、`printed_number`、`prompt`、`slot_id`、有序 Options。
- `prompt = null` 合法，不能过滤图片题或听力题。

### 5.2 RichText v1

- 只接受 `jlptgo-richtext-v1` 白名单节点/mark；未知节点显示安全的“不支持内容”状态并记录诊断。
- 支持纯文本、换行/段落、ruby、underline、cloze slot、block 与 image placeholder。
- 不使用 `dangerouslySetInnerHTML` 直接渲染 Canonical 或来源 HTML。
- Cloze slot 通过稳定 `slot_id` 绑定，不根据可见顺序猜测；重复/缺失 slot 进入明确错误状态。
- 保留日语原文与全角字符；长篇正文可使用受限的日文字体与行宽，但 UI/选项保持 sans。

每种节点建立正常、空值、未知节点、恶意属性、嵌套深度异常的组件测试。

## 6. 听力与媒体

- 第一版仅实现普通练习所需的播放/暂停、进度与加载/失败状态；不实现严格模考播放限制或完整精听系统。
- 媒体 URL 必须来自公开授权 API/静态媒体策略，不能引用 Raw ZIP、内部路径或来源私有文件。
- **媒体读取接口（已落地，2026-11-16）**：`GET /api/releases/{release_id}/assets/{asset_id}`，前端用 Unit 的 `release_id + asset_id` 定位媒体，不自行拼接磁盘路径或 Raw 来源地址。该接口只服务「已发布 Release 且通过 complete Unit 关联、storage 校验通过」的资产；所有拒绝路径统一 404（draft release、未关联资产、storage 缺失/哈希不符、文件缺失）。支持 HTTP Range（206/416、`Content-Range`、`Accept-Ranges`、精确 `Content-Length`）以支持浏览器播放与拖动；内容按 SHA-256 寻址存储（`<root>/<sha[:2]>/<sha[2:4]>/<sha256>.<ext>`），磁盘路径不进入任何公开 DTO。文件由独立的 `python -m app.media_sync` 步骤从确认的本地来源复制、校验后原子落盘；落盘 ≠ 审核通过，服务门槛仍由接口校验。
- 播放器只在浏览器生命周期初始化；预渲染阶段不访问 `window`、Audio API 或 localStorage。
- 普通听力播放器固定在底部时，为页面与 safe area 留出真实高度；360/390px 下不遮挡选项或提交按钮。
- 当前公开 Unit API 不返回 `cues`。M2.2 不得改用 internal API 绕过；字幕是否可在作答前公开需先明确产品/权限规则，并由公开 DTO 有选择地提供。媒体接口的补齐不等于授权作答前公开字幕。

## 7. 草稿、提交与反馈的前端状态机

前端状态至少区分：`idle`、`dirty`、`saving`、`saved`、`save_error`、`conflict`、`submitting`、`submitted`。选项点击只改变草稿，不代表正式答案。

### 7.1 自动保存与恢复

- 页面打开顺序：读取本人 Session → 按固定 Release 读取 Unit → 读取服务端草稿 → 合并本地待重试编辑。
- 保存采用短延迟合并；每题携带服务端返回的 `row_version`/`expected_row_version`。
- 只有服务端确认后显示“已保存”；失败保留当前选择并提供重试。
- 409 版本冲突不静默覆盖：拉取服务端最新草稿，展示差异并让用户选择采用服务端值或以新版本重试。
- localStorage/IndexedDB 只保存最小待重试记录（用户、Session、Question、选项、已知版本、时间）；不得保存答案、解析或把它当正式成绩。
- 刷新、路由返回与关闭页面不主动结束 Session；恢复后已提交 Unit 保持锁定。

### 7.2 Unit 提交

- 提交前按该 Unit 的 Question 集合计算未答数；有未答时显示确认对话框/移动端底部抽屉。
- Loading 期间禁重复点击；服务端目前以已提交状态、行锁和唯一约束保证重复提交返回同一存储结果。网络超时后先查询 Session Unit 状态或反馈，再决定是否重试；前端可生成本地 request ID 做日志关联，但不能把它误称为服务端已持久化的 idempotency key。
- 服务端必须验证选项属于对应 Question；前端校验只用于即时提示，不是安全边界。
- 提交后整组锁定；未答显示 skipped，不显示 wrong。

### 7.3 反馈权限

- `immediate`：只有该 Unit 已正式提交后，才请求/接收该 Unit 的答案与解析。
- `end`：Session 完成前所有 Unit 均不得接收正确答案、`is_correct` 或解析；不能靠 CSS 隐藏。
- 返回字段之外的信息一律视为不可见；前端不预取未来 Unit 的反馈。
- 单 Unit 即时模式原地展示反馈；完整 Session 展示正确/错误/未答、总数、得分率和已作答正确率，避免未经核实的 JLPT 官方换算分。

## 8. 已落地的 Task 05–08 API 契约

以下是 M2.2 当前可直接对接的契约；以现有路由和集成测试为事实基线。后续路径或字段如调整，须同步 API adapter、测试与本文。

| 能力 | 最低请求/响应要求 |
|---|---|
| 查询 Unit 草稿 | 本人 + `session_unit_id`；返回每题 `chosen_option_id`、`row_version`、`updated_at`，不含答案 |
| 保存/清除草稿 | Question、可空 Option、`expected_row_version`；成功返回新版本；旧版本 409 返回 `current_row_version`，前端随后重取草稿 |
| 提交 Unit | `POST .../units/{session_unit_id}/submit`；请求含完整/部分 answers，缺省题按 skip；整组事务；重复请求返回存储结果和 `idempotent=true` |
| 查询 Unit 状态 | 至少可判断 pending/submitted，供超时恢复；权限同本人 Session |
| 即时反馈 | 仅提交后的该 Unit；返回 chosen/correct/is_correct/explanation，未答为 `chosen_option_id=null,is_correct=null` |
| 完成 Session | 各 Unit 先独立正式提交；`POST .../{session_id}/finish` 在全部 Unit 已提交时生成 completed + 结果，否则 ended_early 且不生成完整成绩；两者幂等 |
| 查询结果 | `correct/wrong/skipped/total`、得分率、已作答正确率、完成时间、逐题复盘；三态之和等于 total |
| 提前结束 | 有未提交 Unit 时仍为 `ended_early` 且无虚假完整 `study_results` |
| 读取媒体 | `GET /api/releases/{release_id}/assets/{asset_id}`；仅 published release + complete Unit 关联 + storage 校验通过；统一 404 拒绝；HTTP Range（206/416）；`Content-Type` 来自资产 mime；历史 release 同样可读 |

所有端点必须：从服务端身份取得 `user_id`；跨账号访问统一 404；非本人不可读写；Draft/未审核内容不因答题接口转为公开；Session 始终引用创建时的 Release。

### 8.1 前端接入检查

答题写入 UI 接入时必须验证：

1. 以前端 DTO 钉住现有响应样例，并对未知/缺失字段给出可诊断错误。
2. 将版本冲突、重复提交、未答、即时/统一反馈零泄漏、跨账号访问的现有 PostgreSQL 集成场景加入前端契约/E2E 对照。
3. 正确处理 `finish` 的双重结果：全部 Unit submitted 才是 completed + results；仍有 pending Unit 时是 ended_early，不得在 UI 伪造完整成绩。

## 9. 错误与可访问性

- 统一映射 401（登录失效）、404（不可访问/不存在）、409（活跃会话或版本冲突）、422（Unit/选择不可用）和 5xx；未知错误不得默认可继续提交。
- 单选使用原生 radio 语义或等价可访问模式；键盘、焦点、提交后的读屏公告完整。
- 选中、正确、错误、未答和锁定均使用文字/图标辅助，不只靠颜色。
- 触控目标至少 44px；文本缩放 200% 后核心操作可达；尊重 reduced motion。

## 10. 测试与验收

### 10.1 自动化层级

- 类型/契约：API DTO 运行时校验，未知/缺失字段可诊断。
- 单元：RichText 白名单、slot 绑定、三态统计、错误映射、草稿状态机。
- 组件：选项改选与锁定、保存中/失败/冲突、未答确认、反馈权限、音频失败。
- 路由集成：学习首页恢复、试卷目录、直接刷新 SPA、固定 Release 读取。
- E2E：使用隔离测试库的合成发布内容；未经审核的真实样本不为验收而公开。
- 构建：SSG 初始 HTML、Meta/canonical、`__spa-fallback.html`、公开 404、学习页 noindex。

### 10.2 M2.3 关键场景

| 场景 | 验收 |
|---|---|
| 文字词汇单题 | 作答、保存、提交、即时解析 |
| N2 文法問題9 | 1 Unit / 5 Question；slot 精确绑定；整组锁定 |
| N2 读解問題11 | 三篇文章保持三个 Unit，不错误合并 |
| 听力 | 音频和 Unit/Question 关联正确；字幕仅按已确认权限显示 |

设备至少覆盖 Chrome/Firefox/Safari、1440/1024/768/390/360px；真实长文、看图题、cloze、听力均需走查。

- 不重写 FastAPI、PostgreSQL Schema 或发布审核流程。
- 不接触、迁移或修改 JLPT GO 1.0。
