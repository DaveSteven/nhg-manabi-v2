# ADR-0031：v2 在现有服务器上替换 V1 成为正式版本

- 状态：已确认（用户 2026-11-21：「部署目标就是把 V1 的停掉，V2 做成正式版本」）。具体时间窗口、邮件密钥等执行细节仍待用户逐项授权。
- 日期：2026-11-21
- 关联：ADR-0029（V1 用户迁移）、ADR-0030（扩展练习与作答迁移）、`docs/development/cutover-plan.md`

## 决定

1. 生产目标 = V1 现在所在的服务器（SSH 别名 `manabi`）；v2 沿用现有域名 `jpn.manabi.cc`（学生端）与 `admin.manabi.cc`（管理端）及其现有证书，**不新增域名、不改 DNS**。
2. v2 与 V1 **并存部署、最后切换**：v2 放在独立目录与独立 Compose 项目（独立数据库、卷、端口、nginx 站点文件），不与 V1 共用数据库、卷或目录（延续 `deployment.md`「v2 不指向 V1 数据」的约束；V1 的库只被迁移脚本只读读取）。
3. 切换 = 冻结 V1 → 导入 V1 用户与作答 → 把 nginx 的站点改指 v2；**V1 只停止、不删除**（容器、数据卷、备份、nginx 配置备份保留），观察期满并经用户确认后才进入下线。
4. 回滚 = nginx 切回 V1 站点并重新启动 V1 API；因为迁移只读 V1，V1 数据不受影响。切换后在 v2 产生的新数据不会回写 V1。
5. 本决定不改变：`main` 只在上线成功并经用户确认后才合并；部署、推送、导入都要用户逐项明确授权。

## 影响

- 服务器只有 1.9 GB 内存、3 核、2 GB swap：镜像与前端构建在开发机完成（目标 x86_64，开发机是 arm64，需要交叉构建），服务器只负责运行；并存期间要观察内存。
- V1 的管理员账号不迁移，v2 管理员用 `admin_cli` 新建。V1 用户的登录会话失效，需用原用户名密码重新登录（首次登录哈希自动升级）。
- 旧站点路径（V1 前端路由）会失效；是否加跳转由用户决定。
