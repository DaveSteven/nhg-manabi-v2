# ADR-0007：采用 SSG + SPA 混合渲染架构

**状态：** Accepted（设计决策）
**项目：** nhg-manabi-v2
**日期：** 2026-11-16
**决策范围：** 用户端前端渲染架构

> 注：原建议编号 ADR-0005 已被「审核事件确定性顺序与可追踪 Issue」占用（M1.6），ADR-0006 已被「M2 最小用户身份边界」占用（M2.1 Task 03），故本决策顺延为 ADR-0007。M2 计划 Task 09 中「写入 ADR-0006」的引用同步修正为本条。

## 1. 背景

JLPT GO 2.0 同时承担两类需求：

1. 对外品牌宣传、SEO、原创 JLPT 学习内容展示。
2. 登录后的专项练习、历年试卷、模拟考试及个人学习分析。

两类页面对渲染方式的需求不同。

品牌和内容页面需要稳定的 HTML 输出与搜索引擎可发现性；学习系统则需要频繁交互、客户端状态管理和服务端作答会话。

现有技术体系为 React + FastAPI + PostgreSQL。项目由个人开发者维护，需要控制部署复杂度和服务器成本。

## 2. 决策

采用：

**React Router Framework Mode + 静态预渲染（SSG）+ 客户端学习应用（SPA）**

- 对公开品牌页与原创内容进行静态预渲染。
- 对登录后学习系统使用客户端渲染。
- 保留 FastAPI 作为独立业务 API。
- 保留独立 React 管理后台。
- 第一阶段禁用运行时 SSR。
- 不引入 Next.js 或额外 Node.js SSR 服务。

## 3. 主要理由

### 3.1 兼顾 SEO 和复杂交互

公开内容可直接输出完整 HTML，不依赖搜索引擎执行 JavaScript 才能获取主要正文。

学习系统继续保持 React SPA 的交互方式，适合答题、音频播放、自动保存及即时反馈。

### 3.2 减少技术栈复杂度

继续使用 React，不增加新的全栈框架。

无需同时维护 FastAPI 与额外的 Node.js SSR 服务。

### 3.3 降低部署与维护成本

预渲染内容可作为静态文件部署，适合现阶段 VPS 资源与个人维护模式。

### 3.4 保持未来演进能力

React Router Framework Mode 保留后续启用 SSR 的可能。

未来如公开内容规模扩大，可重新评估运行时 SSR，而无须提前承担相关运维成本。

## 4. 备选方案

| 方案 | 不采用的原因 |
|---|---|
| 纯 React SPA | 公开 SEO 内容的初始 HTML 不够完整，搜索引擎兼容性和内容发现存在限制 |
| 全站 Next.js | 当前阶段增加不必要的框架与服务端部署复杂度 |
| 全站 SSR | 学习系统大量私有页面不需要运行时生成 HTML |
| 官网和学习站两个完全独立项目 | 第一阶段增加设计系统和前端代码维护成本；后续可重新评估 |

## 5. 影响与代价

本决策带来以下约束：

- 品牌首页 `/` 和学习首页 `/study` 必须分离（共用「樱与墨」设计系统，不要求相同布局）。
- 公开内容的修改需要重新构建。
- 动态 SEO 路由需要在构建时明确提供路径。
- Nginx 必须正确区分预渲染页面和 SPA fallback；无效公开路由必须返回真实 404，不得把预渲染的品牌首页 HTML 错用作全站 fallback。
- SEO 页面不得依赖登录状态；公开 SEO 页不得在构建期注入用户身份或私有题目数据（答案可见性红线在预渲染产物中同样适用）。
- 浏览器专属 API 不能在预渲染阶段直接执行。
- 需要维护 sitemap、meta、语言版本及索引策略：仅允许索引的页面进 sitemap；用户/会话/学习历史页面 `noindex`；未授权答案、解析、私有数据不进入任何 SEO 页面；多语言须有独立稳定 URL 与 `hreflang`，未发布语言不入 sitemap。

## 6. 实施范围

本决策影响：

- `apps/web`
- `docs/design/frontend-spec.md`（「页面渲染策略」章节已随本决策落地，为 `apps/web` 的实现规范）
- `docs/design/page-structure.md`
- 前端构建与部署配置
- SEO 页面及多语言 URL 设计

本决策不影响：

- PostgreSQL Schema
- Canonical 题库格式
- FastAPI 业务 API 的技术选型
- 内容校验 Agent
- 已确定的 Unit 作答和会话规则

## 7. 验收条件

- 品牌首页由构建过程生成完整静态 HTML。
- 公开内容页具备可独立索引的标题、正文和 Meta。
- 学习系统作为 SPA 正常工作。
- 刷新与直接访问内部学习路由正常。
- 后端继续由 FastAPI 提供业务 API。
- 不新增运行时 Node.js SSR 服务。
- SEO 页面与用户私有数据有明确隔离。

## 8. 未来复审

当出现以下情形时，重新评估 SSR 或其他渲染策略：大量按请求实时生成的动态公开页、预渲染构建成本明显升高、个性化内容必须服务端渲染、或实际性能/SEO 指标证明静态预渲染成为瓶颈。

未经新的 ADR 决策，不得擅自将整个项目迁移为 Next.js 或全站 SSR。
