# ADR-0013 用户中心与头像

状态：已接受（用户 2026-11-16 指示：参考 v1 做用户中心；首页右上角只显示头像；头像素材沿用 v1，默认纯色头像，可编辑头像与昵称）。

## 决策
1. **顶栏右侧**：已登录显示「备考等级选择器 + 圆形头像」，头像**点击直接进入用户中心**（无菜单，用户 2026-11-16 追加指示）；未登录仍显示 登录/注册。昵称、「退出」按钮不再出现在顶栏，退出登录在用户中心内。
2. **备考等级选择器**顶栏与用户中心两处都有（曾短暂移出顶栏，后按用户指示放回）；等级仍是 `users.current_level`，试卷列表默认筛选逻辑不变。
3. **头像为固定集合**：沿用 v1 的 12 张 256px WebP（柴犬/狐狸/…/锦鲤，id 与文件名相同），不开放自定义上传。`users.avatar`（Alembic 0008，可空，长度 ≤32）为 NULL 时显示**纯色头像**：颜色由用户 id 稳定映射到 4 种强调色，内含昵称首字。允许的 id 白名单在 API 校验（`student_auth.AVATAR_IDS`），非法 id 返回 400 且整次 PATCH 不生效。
4. **`PATCH /api/me`** 增加 `avatar`：字段缺省 = 保持，显式 `null` = 重置为默认头像；可与 `display_name` 同次提交。
5. **用户中心** `/study/account`（SPA，noindex，未登录跳 `/login`），参考 v1 **左右两栏**：左栏身份卡（头像、昵称、邮箱、编辑资料），右栏分组卡（备考目标：目标级别；账号：登录邮箱、退出登录）；≤720px 堆叠为单列。编辑资料为单个弹窗（头像网格 + 昵称，统一保存）。
6. **不做**：学习统计、收藏、连续学习天数等 v1 用户页内容——v2 暂无对应数据模型（`user_question_progress` 留待 M3），不放假数据。修改密码/邮箱同样未做。

## 取舍
- 白名单放在应用层而非 DB CHECK：头像集可增而无需迁移；DB 只限制长度。
- v1 用两级弹窗，v2 合并为一个，减少层级与焦点管理成本。
- 头像素材是 v1 自有资产的拷贝，版权按项目自有内容处理（未在此额外核实原始出处）。
