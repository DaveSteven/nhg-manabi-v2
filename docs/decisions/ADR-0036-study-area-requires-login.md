# ADR-0036 · 学习区统一登录拦截

- 状态：已确认（用户 2026-11-25 要求未登录跳登录页；同日修正：试卷目录与详情可浏览，点「开始练习」才登录）
- 修订：ADR-0011 / ADR-0019 中「游客可浏览目录、顶栏只显示登录/注册」的隐含假设；P-002 导航结构不变。

## 决策

1. `/study/*` 要求已登录学生，**仅 `/study`（首页）、`/study/exams`（历年试卷目录）与 `/study/exams/:id`（试卷详情，不含 `/mock`）允许游客浏览**：`StudyLayout` 在没有 `auth.user` 且不在这两个路径时统一 `Navigate` 到 `/login`，并通过 `location.state.from` 带回原路径（含 query）。登录成功后仅当 `from` 是 `/study…` 站内路径才返回，否则去 `/study`（防开放重定向）。
2. 全局 401 拦截：`apiFetch` 在**携带 Bearer token 的请求**收到 401 时（登录接口本身除外，其 401 表示口令错误）调用 `notifyUnauthorized()`，`authStore` 清除会话，上面的守卫随即把用户送回 `/login`。
3. 开发工具身份 `VITE_DEV_USER_TOKEN`（ADR-0006，生产禁用）视为已登录，不被守卫拦截。
4. 试卷详情对游客只读：不请求练习状态/模考记录；点任一大题/Unit 跳 `/login`，`state` 带 `from`（原页面）与 `intent`（试卷名），登录页显示「登录后继续：<试卷名>」，登录后回到该详情页。
5. 品牌首页 `/`（`/` 另有 nginx 302 到 `/study`，见 P-032）与认证页不受影响。

## 实现（2026-11-25 整理）

守卫是声明式的：`components/RequireAuth`（路径无关布局路由，`routes/_require-auth.tsx`）。`routes.ts` 里**挂在它下面的路由需要登录，其余公开**——不再维护路径白名单。

| 公开（游客可浏览） | 需登录 |
|---|---|
| `/study`、`/study/exams`、`/study/exams/:examId` | `/study` 下其余全部（账户、专项、扩展、学习、答案分布、模考介绍/成绩、练习与结果、dev 工具页），以及布局外的严格模考页 `/mock/:sessionId` |

新增页面默认放进需登录组；要公开必须显式写在 `routes.ts` 的公开段。各页面原有的零散 `Navigate` 已删除（页面内只保留 `if (!auth.user) return null` 做类型收窄）。严格模考页此前不在 `/study` 布局内，现在同样受保护。

## 影响

- 游客仍可看首页与试卷目录，点击试卷（详情）、专项、扩展、学习、账户等一律进登录页；学生端服务端接口（练习、模考、进度）本来就要求登录，后端未改。`/api/exams*` 等内容目录接口仍是公开的，前端守卫不是授权边界。
- 各页面原有的零散 `Navigate to="/login"`（学习页、账户页、模考页）保留，作为纵深防御。
- 若日后要恢复游客试用，应新增 ADR 并为具体页面开白名单。
