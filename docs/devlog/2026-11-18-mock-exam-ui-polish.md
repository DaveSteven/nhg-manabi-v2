# 2026-11-18 · 模拟考试 UI 优化与倒计时修复

## 范围
用户的 5 点方案：胶囊 Header、倒计时修复、独立题型紧凑布局、答题卡 Drawer 重做、当前题定位一致性。不改作答逻辑与后端；不影响文章填空/读解布局。

## 根因：倒计时不走
`useServerCountdown` 每次渲染都用最新的 `server_now` 重新计算「设备与服务器时钟偏差」。秒级重渲染时偏差恰好抵消了流逝的时间，剩余时间永远等于刚加载时的值（1:45:00）。修复：偏差只在**收到新的 `server_now` 时测一次**，其后始终用绝对截止时间 `expires_at − (现在 + 偏差)` 计算，不累计误差；后台标签页恢复可见（`visibilitychange`）时立即重算；到 0 触发既有的重读服务器状态（服务器据此封存阶段）。`MockBanner` 共用同一 hook，一并修复。

## 改动
- Header：`.exam-bar-wrap`（Sticky）+ 与站点 Header 同语言的悬浮胶囊（白底半透明、模糊、圆角 36px、浮动阴影，窄屏 28px）；Logo / 考试名 / 阶段与大题 / 已答进度条 / 倒计时 / 「答题卡」顺序不变，按钮固定在倒计时右侧，间距加大。`--exam-bar-h` 调为 84px 以免 Sticky 面板被遮挡。
- 紧凑布局：卡片间距 16px、卡片内边距 16px、题号与题干 8px、题干与选项 10px、选项 8px；「标记待检查」移到卡片右上角（与题号同行）；当前题只用淡粉底色 + 题号变樱色，去掉整卡粉边框。（`.card` 的 24px 内边距曾覆盖，已提高选择器优先级。）
- 答题卡 Drawer：宽 410px、30% 黑遮罩、柔和阴影无分割线；头部「答题卡」+ 三个独立统计块（已作答/未作答/标记待检查）；每个大题是圆角浅底分组卡，标题 `問題10 · 1/5` + 展开图标，折叠仅标题；题号网格每行 5 个，已答浅樱 / 当前深樱白字 / 标记为右上角旗标且与状态色叠加；Header 与底部操作区固定，仅中间列表滚动；底部「返回作答」+「结束当前阶段 / 检查并交卷」，沿用既有确认逻辑。
- 定位：每次**打开**答题卡都只展开当前题所在大题，并把它滚动到可见（列表内滚动）。当前题改由滚动监听确定（取第一张越过状态栏的可见卡片，隐藏的面板题不参与；从答题卡跳转后 0.9s 内固定目标，避免平滑滚动期间跳回），高亮题号与用户实际看到的题一致。

## 测试（实际执行）
- 前端 `vitest`：36 文件 / **302 passed**（连跑两次稳定）。新增 `useServerCountdown.test.tsx` 4 项（假时钟：每秒递减、设备时钟错误时以服务器为准、重渲染不冻结且到 0 只触发一次 onExpire、后台标签页恢复后追平）；`MockExam.test.tsx` 新增「状态栏时钟真的在走」与「重新打开答题卡只展开当前大题且当前题高亮」，答题卡统计改为三个数字块；放宽了依赖实时时钟的断言。`tsc` 无输出，`npm run build` 通过。
- 真实环境（Docker web 重建，内置浏览器 JS 读取计算样式）：倒计时 37:53 → 3.2 秒后 37:50（正常递减）；Header 为 sticky 胶囊；卡片内边距 16px、列表间距 16px、题号下间距 8px；标记按钮 absolute 右上；抽屉中间区 `overflow-y:auto`、5 列网格、三个统计块、分组标题 `問題1 · 0/5`、仅当前大题展开。
