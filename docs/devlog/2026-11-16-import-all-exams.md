## 过程中发现并修复的两个真实缺陷
1. **媒体格式不支持**：34 个资产被判 `mime_unknown`——29 个 `audio/mp4`（.m4a）与 5 个 `image/webp`，都是合法文件。`sniff_mime` 增加 MP4 音频品牌（M4A/isom/mp42…）与 WebP 识别（拒绝 avif/heic 等非音频品牌、非 WebP 的 RIFF），存储与 API 的扩展名映射同步（测试断言两者一致）。重跑后 4,027/4,027。
2. **连接泄漏（严重）**：`get_engine()` 每次调用都新建 Engine（含独立连接池）且从不释放，每个请求泄漏连接，全量扫描时 Postgres 返回 `too many clients already`，149 个请求 500。改为按 DATABASE_URL 缓存单例（pool_size 5、max_overflow 10），并新增回归测试（同一 URL 复用、60 次调用服务端连接数不增长）。**这会让服务在真实流量下崩溃，是本次最重要的发现。**
